# 组件与私有内部节点：工作区提案

日期：2026-09-17。状态：`superseded`（2026-09-26 R0.3 权威清理）。

本文保留早期交互探索的历史记录，不作为待执行计划。当前界面以 [组件编辑器修正](component-editor-redesign.md) 为准；当前能力与阶段以 [PLAN](../../PLAN.md) 和 [M10 治理](../governance/m10-3d-delivery-governance.md) 为准。以下“方法实现编辑器”“私有节点方法”“受控调用创作”等建议均未获准实现。

## 用户澄清与设计修正

“图层”是待开发组件内部的对象：具有稳定 ID、名称、属性及类型提供的方法，能力只供所属组件内部使用。图层树表达层级与排序，不应把对象能力限制成图形外观。外层组件显式声明自己的公开接口，内部节点的能力不会自动对外暴露。

上一批对象页签解决了现有表单的归属，但把“组件配置”和“内部对象配置”放在同一个检查器中，不能满足编写组件逻辑时持续查看内部对象能力的工作流。

## 推荐布局（采纳用户后续提出的中央工作页方向）

- 右侧固定承担“所选内部节点检查器”：名称、稳定 ID、类型，以及该节点实际提供的可编辑属性、可调用方法、可监听事件。选择节点会更新右侧；空选择显示节点选择提示，不自动切成组件定义。
- 左侧保留素材与内部结构树，负责选择、层级、排序。组件定义无需伪装成根图层。
- 中央使用紧凑的纯图标 Segmented Control 切换“画布／组件定义”：绘图图标对应画布，组件图标对应组件定义；浅中性底轨、白色选中滑块、青绿色选中图标，默认 68×28px，复用中央工具区的导航空间。名称仅作为悬停/键盘提示与无障碍标签，选中块和面板推拉使用相同的时长与缓动。触摸设备扩大到 44px 操作区域。两段明确归为一组，不使用页签下划线或宽铺的页签栏。它们是工作内容，不改变全局设计/预览模式；预览仍遵守现有只读门禁。
- 画布工作页用于空间设计，不常驻底部检查器。组件定义工作页用于基本信息、公开属性、方法签名/参数及事件载荷；方法实现编辑器也放在这里，使用足够的中央宽度。
- 在组件定义页选中其他节点，只改变右侧检查器，不跳回画布、不替换当前方法，也不移动方法编辑器的插入位置。右侧能力可以查看类型和参数，并插入引用/调用。
- 工作页切换保留画布缩放、位置、选择，组件页分类、滚动位置、草稿与编辑器光标；所有更改仍归属同一组件文档、保存状态和撤销历史。不得因组件页被隐藏而丢草稿或自行提交。
- SVG 源码等复杂内容通过右侧“编辑 SVG 源码”显式打开中央内容编辑区，标题明确真实目标，保留返回画布入口。之后选择其他节点仍可查看能力，不得静默替换正在编辑的源码。
- 只有实现了对应能力的节点显示其入口；不为每一种类型统一摆出空白方法/事件页签。

用户进一步提出希望保留部分画布、采用顺滑推拉切换。最新提案采用中央区域内的推拉面板：组件定义从右侧进入，默认约 280ms，采用快速启动、平缓结束的缓动，不弹跳；画布轻微后退，保留真实画布边缘，默认 56px。左右两侧保持稳定，不使用遮住全屏的暗色模态背景。露出的画布边缘可点击返回，关闭后焦点回到“画布”分段控件。

留白是维持空间关系和提供返回入口，不能强行牺牲编辑宽度：中央小于 420px 时缩为 28px，小于 340px 时不留边缘。长代码编辑可以选择占满中央区域。用户开启减少动态效果时立即切换；快速往返切换可以平滑反转动画，不排队播放。草图提供保留宽度、过渡时长和占满中央三个可调项。

推拉仅是同一工作页切换的视觉表达。画布和组件定义保持挂载，关闭内容退出键盘焦点序列，动画不会提交/清空草稿，也不会改变节点选择或画布设计尺寸。

前一版“右侧固定组件，底部跟随节点”作为备选保留，但不再推荐为默认：它常驻占用画布高度，节点方法签名也更拥挤。新的方案让编写组件实现与查看节点能力同时可见，也符合用户希望把画布空间留给设计的目标。

## 类型化编辑范围

- 文本：内容、排版及该类型提供的内部能力。
- 图元/路径：几何、外观与对应能力；复杂路径可进入中央编辑区。
- SVG：元素结构、属性、内部引用，以及源码编辑/预览；完整源码修改需要校验、错误定位、应用与撤销。
- 图片：资源、适配、裁剪等真实支持的操作；不提供 SVG 源码入口。
- 组合：层级与组合能力；沿用已确认规则：画布操作整组，内部节点可配置属性和行为，几何/形状修改必须先拆分。组合内 SVG 可查看源码，任意结构/几何源码修改同样不能绕过拆分要求。

这里列的是设计职责；未实现的裁剪、私有方法等不能用空按钮假装可用。方法清单来自节点类型能力定义，而不是所有节点统一附加一个任意方法表单。

## 现状与实现边界

`ComponentVisualLayer` 当前只有 group/svg/image/vector/text 的图形数据。`ComponentDefinition.actions/events` 是外层公开契约；现有 Controlled Runtime 提供组件属性/方法/事件和有限的图层 visual 操作，没有通用私有节点方法注册与调用协议。应补齐这个模型，不能把现状误当成产品目标，也不能只移动页签就宣称私有方法可用了。

SVG 已有 `ManagedSvgDocument` 作为正式数据来源，现有规则定位使用稳定 `(layerId, svgTagId)`，`authorRef` 只是作者别名。当前源码导入会分配元素标识，不能直接用“重新导入整个字符串”实现编辑保存：否则已有引用可能丢失或误指。

源码编辑应保留独立草稿，经解析和支持范围校验后，对照原文档保留未变元素的稳定标识；处理删改元素的引用影响；最后一次提交到同一个文档历史。无效 XML 不替换有效画面。需补充增删/重排元素、改源 ID、重命名别名与撤销/保存重开测试。源码仍是静态 SVG 资源，不把脚本塞入 SVG 绕开组件受控方法运行。

## 可续接的小批次

1. 布局批次：右侧保持节点检查器；中央用 Segmented Control 切换画布/组件定义两个工作页，迁移现有组件定义表单。先只搬迁真实已有能力，验收选择、画布视图、滚动、草稿与光标不互相打断。
2. SVG 批次：中央源码编辑器、校验/预览/应用、一次撤销、稳定元素标识与引用保持。先完成可测的安全往返，不混入运行模型扩展。
3. 私有能力批次：按节点类型定义属性的可读写性、方法参数与事件载荷；区分类型提供的能力与节点实例状态。限定所属组件内解析和调用，外部仍只能访问组件公开契约。
4. 调用创作批次：组件方法编辑器自动补全内部节点、查看签名与插入调用，接入受控运行及错误定位；验证组件包、预览和独立运行使用同一条能力解析路径。

本次仅提供方案和可交互草图。工作区已有用户对排序按钮的四个未提交文件修改，均未更改。中央工作页草图已经验证节点选择独立、方法草稿/插入位置保持、源码编辑目标保持、无效源码不替换预览及 320–1024px 布局。
