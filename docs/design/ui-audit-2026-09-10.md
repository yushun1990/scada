# SCADA Studio UI 设计与实现审计

日期：2026-09-10。审计基线：`2de5a35`。2026-09-11 在同一源码基线上完成续接复核，结果见第 7 节。

交付范围：现状审计、Ignition Designer 对照、修正设计规范与推进计划。本次不修改产品功能代码。

## 1. 结论

当前产品已具备工业组态编辑器的核心能力和三栏骨架，但距离稳定的专业工作台仍有明显差距。优先问题是编辑事务、保存反馈、模式边界和选择范围；视觉问题集中在字号过小、层级表达不统一和样式覆盖积累。

建议以 **Ignition 8.3 Designer 的工作台组织方式**作为参照，形成适合浏览器的 SCADA Studio 设计系统：中性灰工作区、清晰文档身份、菜单与命令工具栏、资源/图层导航、可搜索属性表、可恢复的面板布局、明确的预览与数据状态。尺寸和色值采用本项目的规范，不宣称与 Ignition 像素一致。

- [推进计划与验收门槛](industrial-designer-rollout.md)：按依赖顺序拆解工作。

## 4. 按优先级排序的问题

优先级：P1 = 影响编辑可靠性、核心工作流或关键可读性；P2 = 影响效率、一致性和可维护性。当前没有足够证据将任何条目认定为生产设备安全事故级 P0。

| ID | 级别 / 证据 | 当前问题及影响 | 修正与验收重点 |
| --- | --- | --- | --- |
| A01 | P1 / 源码确认 | 两个编辑器手动保存；返回工作台直接改 hash。缺少统一 dirty、saving、saved、error 状态与离开保护，未保存修改可能随页面卸载丢失。Component 保存完成后直接 `setComponent(saved)`，存在覆盖保存期间新编辑的路径。 | 显示文档名与未保存标志；统一保存状态；返回、切换、刷新覆盖未保存处理。保存失败保留当前文档，成功只确认提交的 revision。 |
| A02 | P1 / 源码确认 | SCADA 部分字段先 `setScene` 后无参数 `commit()`，历史 hook 对当前引用直接返回，无法形成独立撤销记录；其全局 Ctrl/Cmd+Z 与画布 Space 缺少输入焦点、IME 过滤。Component 已有图形撤销及文本目标过滤，但历史仅保存 visual，不覆盖完整组件契约。 | 编辑开始保留 before，提交一次 after；输入内优先文本撤销；取消恢复 before。两编辑器采用一致事务约定，Component 历史覆盖契约及引用协调。 |
| A03 | P1 / 源码确认 | Component Editor 用 `editingDisabled` 区分预览；SCADA 工具栏、属性编辑和全局撤销缺少等价模式门禁。选中对象后切预览仍有写入设计状态的路径。 | 命令执行入口统一校验模式；预览仅改变会话值，退出预览不改设计文档。 |
| A04 | P1 / 源码确认 | 多选时“批量属性”与 `primaryNode` 的标识、几何、组件配置同时渲染；名称/几何改最后所选，显隐/锁定又作用于全部所选。 | 多选只呈现共同可编辑字段，混合值有明确状态；显示目标数量；不暗中将单对象编辑混入批量面板。 |

### 4.2 编辑事务问题的具体推导

```text
修改名称
  → updateNode() → setScene() 替换当前 scene
  → onBlur → commitScene() → commit(undefined)
  → resolveScene(scene, undefined) 返回当前 scene
  → resolved === scene → return
  → 本次名称编辑未入历史栈
```

这是源代码可确定的路径，并非通过浏览器操作得出的复现记录。验收时必须包含“已有历史操作 → 修改名称 → 撤销 → 重做”，防止只测新增/拖拽而漏掉表单编辑。

### 4.3 样式审计量化结果

对 `src/**/*.css` 做静态声明统计：

| 指标 | 结果 | 解释 |
| --- | --- | --- |
| CSS 文件 / 行数 | 22 / 5,818 | 源文件规模，不是传输大小 |
| 8px 或 9px 的 font-size 声明 | 42 | 包含可能被覆盖的历史规则，不等同于 42 个可见缺陷 |
| tokens.css 之外的颜色字面量 | 505 次、137 个不同字符串 | 正则覆盖 hex / rgb / rgba；包含重复、同色异写和合理例外，不能称为 137 种实测页面色彩 |
| 两个编辑页面 | 1,329 / 902 行 | 是职责集中风险指标，不是单独判错依据 |

按 sRGB 相对亮度公式计算候选前景/背景组合：

| 颜色对 | 对比度 | 审计判断 |
| --- | --- | --- |
| `#94a3b8` / `#f5f6f7` | 2.37:1 | 不适合关键辅助文字 |
| `#98a2b3` / `#ffffff` | 2.58:1 | 契约 key 若以此呈现，可读性不足 |
| `#64748b` / `#f5f6f7` | 4.40:1 | 未达到普通文字 4.5:1 门槛，不能向上取整判通过 |

普通文字以 4.5:1 为验收目标；这里是色值计算，最终仍需确认计算样式、实际背景和透明度。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 5. Ignition 参考边界

| 参考点 | 本项目采用方式 |
| --- | --- |
| 菜单、命令栏、资源页签 | 为文档与命令提供固定位置；第一阶段只实现单活动文档，不虚构多文档会话 |
| 可停靠面板与布局恢复 | 先支持左右宽度、折叠、显隐、重置；自由拖停靠与跨窗口后置 |
| Project Browser | 映射到本地作品/组件导航及当前文档图层，不引入新的工程持久化模型 |
| Property Editor | 使用选择上下文、搜索、分组和逐属性绑定入口 |
| Component Palette | 保留 UX1 的左侧创建流程；统一视觉与搜索，不因参照截图搬迁已验收交互 |
| Tag Browser | 借鉴来源选择方式；仅展示当前真实可用数据源，不伪造网关/OPC/MQTT 接入 |

依据：[Ignition 8.3 General Designer Interface](https://docs.inductiveautomation.com/docs/8.3/platform/designer/designer-user-interface)、[Perspective Designer Interface](https://docs.inductiveautomation.com/docs/8.3/ignition-modules/perspective/perspective-designer-interface)。上表右列是本项目的设计决策。

Designer 工作台与运行 HMI 分别规范：编辑器的蓝色用于选择/焦点；运行画面采用中性设备表达，异常状态结合文字、图形与颜色。不能把灰色误用为“离线即正常”，也不能从单一红/绿外观推断设备状态。[Ignition High Performance HMI Techniques](https://www.docs.inductiveautomation.com/docs/8.1/ignition-modules/vision/common-tasks-in-vision/high-performance-hmitechniques)

本次没有做 ISA-101 / ISA-18.2 全文合规审查，不作标准符合性认证；也没有确认现场设备、报警优先级和操作权限模型。
