## 1. 执行目标与顺序

目标是在保持现有 Scene、组件、运行时和分发能力的基础上，建立可信、可读、可持续扩展的工业编辑工作台。

```mermaid
flowchart LR
    A["A 视觉与任务基线"] --> B["B 保存、事务和模式"]
    B --> C["C 设计 token 与共用 Shell"]
    C --> D["D 导航和属性表"]
    D --> E["E 工作台与诊断"]
    E --> F["F 回归与实机验收"]
```

源码已确认的 B 类缺陷可在补充 A 类截图的同时定位和修复；视觉尺寸结论须通过 A/C 的浏览器结果校正。不等待颜色方案完成才处理数据可靠性问题。

## 2. 排期假设

估算以一名熟悉项目的前端工程师、按需参与的设计与 QA 为前提；是实施工作量区间，不是已承诺日期。

| 批次 | 建议时间窗 | 主责 | 工作量 | 对应审计 |
| --- | --- | --- | --- | --- |
| A 基线与任务验收清单 | 第 1 周开始 | 设计 + QA + 前端 | 1–2 人日 | A06–A13 的视觉证据 |
| B 编辑可靠性 | 第 1–2 周 | 前端 | 4–6 人日 | A01–A04 |
| C 视觉系统与共用 Shell | 第 2–3 周 | 前端 + 设计 | 4–5 人日 | A06–A08、A13 |
| D 导航与 Inspector | 第 3–4 周 | 前端 + QA | 6–8 人日 | A04–A05、A09、A12 |
| E 工作台与问题反馈 | 第 4–5 周 | 前端 + 设计 | 3–4 人日 | A10–A11、A13 |
| F 验收与收口 | 第 5–6 周或前批次完成后 | QA + 前端 | 2–3 人日 | 全部 |
| 合计 | 约 4–6 周 | — | 20–28 人日 | — |

估算不包含新协议/网关、完整报警系统、多文档会话、自由停靠、全新组件市场、大规模 HMI 主题改造。组件全域撤销若暴露跨契约协调问题，B 批次需重新估算；不能为了赶排期省略恢复正确性。

## 3. 工作包与验收门槛

### A：建立可比较基线

交付：固定测试作品、固定组件、截图清单、任务记录模板、真实问题复现记录。

- 测试作品含普通组件、组合、连线、可见/隐藏/锁定、静态配置、绑定和长名称。
- 测试组件含多个顶层图层、显式 Group、SVG 内部对象、运行属性、规则和动画。
- 使用已有 browser fixture 工具准备数据，不污染用户本地作品。
- 在浏览器可用后补齐 1366×768、1440×900、1920×1080 的关键状态；检查 125%/150% 浏览器缩放及 DPR 2。
- 区分浏览器缩放、操作系统 DPI 与画布缩放，记录每项具体设置。
- 对齐文档权威：新的设计规范为目标；旧文档为历史记录；现有架构收口不重新打开。

验收：每个 P1 有明确触发步骤、预期结果和回归检查（草案见[审计验证清单](ui-audit-2026-09-10.md#44-p1-验证清单)）；视觉状态有同一提交、同一数据的基线。当前 CUA 无浏览器连接是本次证据缺口，不能标记为“已视觉验收”。

### B：先完成可信编辑

建议拆为三组可独立评审的 PR，顺序推进：

| PR 包 | 内容 | 主要落点 | 必须验证 |
| --- | --- | --- | --- |
| B1 编辑事务与快捷键作用域 | 修复 setScene/commit 无参数路径；表单 begin/update/commit/cancel；统一画布与表单历史约定；Component 文档历史覆盖公开契约与图形；输入/IME 排除全局快捷键 | `src/scene/use-scene-history.ts`、两 EditorPage、`src/renderer/SceneRenderer.tsx`、组件引用协调代码 | 新增→改名→改数字→撤销/重做顺序正确；Escape 取消；文本 Ctrl+Z/Space 不改变画布 |
| B2 保存状态与离开处理 | saved revision / dirty；异步保存反馈；保存并继续/放弃/取消；所有离开入口一致；处理保存中的继续编辑 | `src/App.tsx`、两 EditorPage、现有 repositories/storage | 成功、失败、保存中继续修改、返回/浏览器后退/刷新；失败后文档仍在 |
| B3 模式和选择范围 | 共用命令 enable 条件；SCADA 预览门禁；多选先移除单选表单，保留明确支持的批量字段 | ScadaEditorPage、ComponentPropertiesInspector、命令接口 | 预览不能改设计；退出不污染设计值；多选不会无提示只改 primaryNode |

边界：不改变持久化 Schema；命令接口先统一状态检查与事务，后续 C 批次再接菜单。不得只禁用按钮而留下快捷键/回调写入路径。

退出门槛：A01–A04 对应的模型/交互证据通过，且 existing 场景与组件编辑流程不退化。批量属性的完整 mixed-value 体验在 D 完成，B 先让作用范围准确。

### C：统一视觉系统和工作台壳

建议拆为 C1 primitive/token、C2 Shell/layout 两个 PR 包。

- 将新 palette、字号、行高、圆角、边框、焦点和密度写入 `tokens.css` 与 primitive 样式。
- 建立控件状态样本，覆盖 default/hover/focus/pressed/disabled/read-only/error/mixed。
- 增加或扩展 `Menu`、`Dialog`、`SplitPane`、`StatusBar` 等 Studio primitive；使用 Base UI 负责适合的行为。
- 提取 `StudioShell`：菜单 28、主工具栏 36、文档条 28、状态栏 26、左右面板 248/320。
- 显式插槽接收工作台导航，移除 `StudioWorkspaceExit` 的 DOM 查询与 MutationObserver。
- 菜单、工具栏与快捷键调用 B 的命令接口；溢出菜单和面板隐藏/恢复可键盘访问。
- 收敛旧 CSS：逐区域迁移，删除对应旧声明，不额外叠一份“最终覆盖样式”。处理未分层规则和 lazy CSS 顺序。
- 同步旧 ui-foundation 与 ui-primitives 引用关系；按组件语义设置主按钮，不用 first-of-type。

退出门槛：

1. 两编辑器直接进入和往返切换均保持样式一致。
2. 1366×768 下保存、模式、工具菜单、Inspector 和状态栏可见可达。
3. 关键文字与控件边界通过实际颜色对比检查；普通字段不小于 12px。
4. 主工具栏不换成两行；溢出有明确入口；调整/隐藏面板不会重置文档或选择。
5. 保存和历史测试仍通过。

### D：完成工程导航与属性表

建议拆为 D1 Navigator、D2 PropertyRow/binding、D3 多选与可访问结构三个 PR 包。

- 在 SCADA 实现真实 Scene Navigator；复用 Component 的搜索/定位交互经验，使用不同领域 adapter。
- Palette 增加搜索与分类；未实现资源面板从常规导航移除；保留实际文件导入能力。
- Component Navigator 保持真实图层 forest；托管 SVG 的选择、引用与规则目标沿用现有权威。
- `PropertyRow` 统一标签、输入、单位、绑定入口、错误和可复制详情。
- Inspector 搜索、折叠恢复、只读状态；复杂规则/动作按需展开。
- 绑定详情只接现有兼容来源；区分设计值、当前值和缺失来源；不扩建运行时。
- 多选共同字段、mixed value、布尔三态和修改对象数量完整落地。
- 完成 Tabs.Panel 关系、Tree 键盘导航和选择语义；不以添加 ARIA role 替代实际键盘行为。

退出门槛：通过真实 UI 找到隐藏/锁定/深层对象；Canvas/Tree/Inspector 同步；数据来源可解释；Attributes 不出现绑定入口；多选修改和撤销均明确。

### E：收敛工作台、诊断与用户语言

- Works 与 Components 统一表格交互、搜索、排序和空/加载/失败状态。
- 移除假预览；真实缩略图可在有缓存/生成策略后加入，首轮允许只有文件符号。
- 调试、存储管理、数据重置进入工具/帮助菜单；重置仍保留危险操作处理。
- 区分完整作品、场景结构、组件包、调试快照四种文件入口与用途。
- 问题区聚合已有解析、绑定、保存、导入错误，支持定位；不新增报警运行时。
- 统一中文术语，删除 M8/ComponentRegistry 等普通流程中的实现文案；高级详情保留可复制 key。
- 按本批次实际完成情况更新 README 的产品能力说明；M9 / Scene v8 的历史滞后已在 2026-09-11 文档复核中修正。
- Standalone 只更新加载、错误、作品信息和状态呈现，不加入作者工具栏。

退出门槛：首用用户能完成新建/导入/编辑/保存/导出；文件用途清楚；错误可恢复；无假功能和假数据状态。

### F：回归、实机任务与收口

最终收口只对完成的工作标记 accepted。不能把“设计规范完成”“构建通过”写成“UI 改造完成”。

| 验证层 | 范围 | 证据 |
| --- | --- | --- |
| 静态与构建 | build、lint、primitive 边界、已迁移 CSS 无新增硬编码回流 | CI 结果与基线差异 |
| 状态与事务 | 撤销/重做、保存 revision、模式门禁、多选 | 针对行为的模型测试 |
| 交互 | 输入提交/取消、键盘/IME、焦点、面板布局、查找定位 | 浏览器断言与失败截图 |
| 视觉 | 两编辑器、Workspace、Runtime 的关键状态与尺寸 | 当前提交截图与计算样式检查 |
| 领域回归 | M9 权威、SVG 目标、组件/作品包、fresh standalone | 复用既有 model 与 smoke 路径 |
| 部署 | 实际静态资源、lazy CSS、页面直达/往返 | 按 PLAN 的部署后 smoke 要求记录部署版本 |

浏览器覆盖：关键编辑与指针流程使用 Chromium / Firefox；优先扩展 `pages-component-navigation-smoke.mjs`、`pages-component-toolbar-smoke.mjs`、`pages-editor-header-smoke.mjs` 和分发/运行 smokes。改变 Shell 后应更新合理的定位方式，不删掉因产品回归而失败的断言。

首轮固定任务，记录完成/失败和耗时；完成时间作为改进指标，不用未经测量的绝对秒数作为承诺：

1. 创建作品，搜索组件并添加，重命名、调整几何、撤销和重做。
2. 创建组合，定位深层对象，多选修改共同字段并撤销。
3. 修改静态配置，绑定运行属性，进入预览，辨认来源与当前值，再回到设计。
4. 创建组件，放置图元，导入 SVG，修改内部目标规则，保存重开。
5. 模拟保存失败和无效导入，定位原因并恢复工作。
6. 导出组件/完整作品，在新上下文导入，使用独立运行器加载同一作品。

最终门槛：P1 全部关闭；未完成 P2 逐项说明影响与后续归属；核心任务无数据丢失、模式污染和修改范围歧义；截图、提交 SHA、浏览器设置和测试结果可追踪。

## 4. 工程实施映射

下列新文件名是建议落点，不是当前已存在的 API。

| 领域 | 现有代码 | 建议收敛方向 |
| --- | --- | --- |
| App 壳与导航 | `src/App.tsx`、两 EditorPage | `src/features/studio/StudioShell.tsx`，显式插槽与 route leave 协调 |
| 命令与文档状态 | Scene history、各 page 的 handler | `src/editor/commands.ts` / 文档会话接口；领域 adapter 保留独立 Schema |
| 外观 | tokens、foundation、多个全局/feature CSS | token → primitive → shell → feature；每迁移一块移除其旧覆盖 |
| 树与面板 | ComponentVisualTreeEditor、SCADA placeholder | `src/ui/Tree.tsx` / `SplitPane.tsx`，Scene/Component 数据 adapter |
| 属性 | ComponentPropertiesInspector、各 contract editor | `src/ui/PropertyRow.tsx`；字段和绑定详情复用布局与交互 |
| 诊断 | scattered message / toast | 文档级问题展示；仍消费现有解析/校验结果 |

拆分以减少职责和稳定边界为目标，不按文件行数机械拆文件。没有必要引入完整 IDE 框架或更换 Base UI / Konva。

## 5. 发布、回退与风险控制

- 每个 PR 保持可运行，只迁移一组明确定义的职责；不同时重写运行时与 UI。
- B 修改编辑事务需要重点验证引用协调和选择快照；出现异常时回退对应代码，不回滚用户数据 Schema。
- C 先完整迁移一个共享区域再接另一工作台；避免长期保留两套产品主题开关。
- 布局偏好有默认值、版本和重置；无效偏好回落默认，不阻止加载文档。
- 每批都保留上一个可部署版本；若失败涉及保存、预览或包可移植性，不带病进入下一视觉批次。
- 底部问题面板仅使用现有错误信号；缺质量/时间戳时显示未知，不以模拟值填补真实运行状态。

## 6. 后置项

首轮完成后才评估：多文档会话、任意停靠/跨窗口、完整 Tag Browser、真实协议接入、暗色主题、触屏 HMI 主题、报警工作台、组件目录扩张。

重新评估的触发条件是明确用户任务和现有能力不足的证据。单纯为了看起来更像 Ignition，不应引入不存在的网关、项目树持久化结构或运行命令能力。
