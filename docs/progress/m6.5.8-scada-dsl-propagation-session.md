# M6.5.8 — SCADA DSL propagation session

Status: accepted checkpoint, transaction semantics refined

## Goal

Turn the M6.5.7 compiled reverse index into a host-owned propagation session that can safely carry one source/property change through derived Component Properties before evaluating one-shot Component Actions.

This remains a runtime-only layer. It does not change Scene persistence, the authoring DSL surface, or the renderer/device ownership boundary.

## Propagation semantics

For one source update:

```text
source property changes
        ↓
compiled reverse index
        ↓
affected Value Bindings
        ↓
stage changed derived Component Properties
        ↓
route staged Component Property changes through the same index
        ↓
repeat until declarative values are stable
        ↓
evaluate affected Behaviors once against the settled staged state
        ↓
commit runtime-local state
        ↓
return final Property / Component Action effects to the host
```

The staging boundary is important. A Behavior must never observe an intermediate derived Property and emit a transiently wrong Action before downstream Value Bindings settle.

Only the final write for one Component Property is exposed to the host for the transaction.

## No-change suppression

If a Value Binding evaluates to the same effective Component Property value, propagation stops at that edge. No downstream binding is woken and no one-shot Behavior is replayed merely because the same telemetry value arrived again.

## Component Property and Event inputs

The session exposes explicit host entry points for:

- source Property changes;
- host-owned Component Property changes;
- Component Events;
- Primary Device rebinding.

Component Events remain isolated from telemetry propagation and only return concrete Device Action effects for the host to execute. Event Action arguments read the session's latest committed derived Component Property state.

## Primary Device rebinding

`device.*` remains relative. Rebinding the component instance changes only the session Primary Device Context. The same parsed DSL, semantic plan, and compiled reverse index are reused.

Behavior branch state is reset on rebind so the new device state is reconstructed deterministically.

## Cycle policy

Value Binding cycles through `component.*` dependencies are authoring errors, even if a mathematical fixed point could exist.

Examples:

```text
component.a = component.b
component.b = not component.a
```

or:

```text
component.a = component.a
```

Cyclic Value Bindings are detected structurally before propagation, isolated from the propagation graph, and reported as `cycle` diagnostics. Independent acyclic bindings continue to run.

This keeps SCADA derived state declarative; users do not need to reason about fixed-point programs.

## Hard propagation limit and rollback

A bounded `maxPropagationSteps` guard remains as a secondary deterministic safety limit after structural cycle isolation.

Propagation is transactional. If the hard limit is exhausted:

- the transaction is marked aborted;
- staged Component Property values are discarded;
- Behavior branch state is not committed;
- no partial Property update escapes to the host;
- no Component Action effect escapes to the host.

The same compiled program commits atomically when sufficient propagation budget is available.

## Ownership boundary

The session owns only runtime-derived Component Property values, Behavior branch state, Primary Device context, and structural diagnostics. It does not directly:

- mutate the renderer;
- invoke Component Actions;
- invoke Device Actions;
- persist runtime values;
- modify authored component definitions.

It returns Property updates / Component Action effects / Device Action effects for the surrounding host to apply.
