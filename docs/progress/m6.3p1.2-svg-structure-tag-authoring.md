# M6.3P1.2 SVG structure/tag authoring

Status: **accepted · 2026-09-04**

## Accepted gate

M6.3P1.2 exposes the safe retained managed-SVG hierarchy in Component Workbench without creating a second renderer/runtime authority.

Accepted implementation:

- nested retained SVG elements are shown in source/paint order;
- element type and stable private `svg-tag-*` identity are visible;
- source `id` is only a human-readable hint, never target authority;
- internal tag selection is independent from outer SVG Layer selection;
- static authoring writes only `fill`, `stroke`, `stroke-width`, `opacity`;
- clearing a field removes the controlled attribute and restores normal SVG inheritance;
- edits mutate the canonical `ManagedSvgDocument` immutably;
- canonical `assetRef` is regenerated from the authored document after each accepted static edit;
- unsupported/meta structure remains visible but not arbitrarily editable;
- legacy opaque SVG remains whole-resource only until explicit managed replacement.

The renderer remains:

```text
managed document
    ↓ canonical serializer
existing browser Image / Konva.Image path
```

No DOM SVG runtime, per-tag React renderer, per-tag Konva renderer, sidecar static-style tree, arbitrary XML/CSS editor or Path-point editor was introduced.

## Validation / deterministic proof

`scripts/check-managed-svg-authoring.ts` proves:

- two different nested tags can receive independent authored fills;
- previous managed-document snapshots remain immutable;
- retained `svg-tag-*` identities remain stable;
- JSON save/reload preserves identities and authored values;
- canonical serialization and `assetRef` remain deterministic;
- empty values restore inheritance;
- missing tags, invalid opacity/stroke-width and unsafe/external values fail closed.
