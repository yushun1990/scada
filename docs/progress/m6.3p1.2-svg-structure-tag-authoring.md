# M6.3P1.2 SVG structure/tag authoring

Status: **implementation complete on branch · acceptance pending**

## Gate

This slice implements only **M6.3P1.2 SVG structure/tag authoring** after merged P1.0/P1.1 authority and ingest work.

It does not implement P1.3 SVG internal Visual Rule targeting and does not reopen M8/M9 authority.

## Authority carried forward

Managed SVG remains:

```text
SvgVisualLayer.document
        ↓ canonical serializer
SvgVisualLayer.assetRef
        ↓ existing browser Image / Konva.Image path
CompositeComponentVisualRenderer
```

`document` is the only authored internal SVG truth. P1.2 does not add a sidecar style tree, DOM selector authority, React SVG renderer or per-tag Konva renderer.

Internal selection is Workbench UI state only. The persisted identity remains each managed element's stable `svg-tag-*` `tagId`.

## Authoring surface

A selected managed SVG layer now exposes its retained internal hierarchy in Component Workbench.

The tree:

- shows nested retained SVG elements in source/paint order;
- shows element type and stable private `tagId`;
- may show the source `id` only as a human-readable hint;
- lets the author select one internal tag independently from the outer SVG layer selection;
- keeps definition/meta nodes visible while making them structure-only when the P1.2 presentation subset is not meaningful.

Legacy/opaque SVG layers remain whole-resource layers and do not pretend to expose an internal editable tree. Replacing them through the normal managed SVG ingest path is still the explicit conversion boundary.

## Controlled presentation subset

P1.2 writes only the subset frozen by P1.0:

```text
fill
stroke
stroke-width
opacity
```

The UI does not expose arbitrary XML attributes, unrestricted CSS, source-id targeting, Path point editing or structural element creation.

An empty authoring value removes the controlled attribute so normal SVG inheritance/default behavior resumes.

Static edits call the pure managed-document authoring helper:

```text
(tagId, controlled field, value)
        ↓
immutable ManagedSvgDocument update
        ↓ assertManagedSvgDocument
canonical data:image/svg+xml assetRef regeneration
```

Existing tag IDs, child order, unedited attributes and text nodes are preserved.

## Validation / fail-closed behavior

The authoring helper rejects invalid edits before they become component state.

In particular:

- missing `tagId` fails;
- structure-only tags cannot be edited through the presentation surface;
- opacity must remain within `0..1`;
- stroke-width is limited to a non-negative numeric/unitless-or-px authoring form;
- presentation values cannot tunnel multiple CSS declarations;
- the existing managed SVG validator still rejects script/external/unsupported URL/reference semantics;
- the resulting document is revalidated before it can replace the current visual snapshot.

A failed edit therefore does not mutate the previous document or derived `assetRef`.

## History / save behavior

Tag editing uses the same existing `onChange(ComponentVisualDefinition)` path as every other Component Visual edit.

There is no second SVG-specific history store. The existing Component Visual canvas history owns undo/redo, and normal Component Workbench persistence owns save/reload.

Because each accepted edit replaces the managed document immutably and immediately derives the matching `assetRef`, the existing visual validation invariant remains:

```text
assetRef == serializeManagedSvgDataUrl(document)
```

## Renderer boundary

No runtime renderer change is required for P1.2.

The existing Composite renderer already serializes managed `document` and feeds the result through the existing image/Konva path accepted in P1.1. Therefore authored tag values appear in preview without materializing internal SVG elements as renderer nodes.

## Deterministic proof

`scripts/check-managed-svg-authoring.ts` proves:

- `svg-tag-000005` and `svg-tag-000006` accept two independent authored fills;
- the previous managed document snapshot remains immutable;
- all retained `svg-tag-*` identities remain stable after edits;
- JSON save/reload preserves both target identities and authored values;
- canonical SVG serialization contains the two distinct authored values on their original targets;
- canonical `assetRef` follows the authored document deterministically;
- empty values remove the controlled attribute and restore inheritance;
- invalid opacity/stroke-width, missing targets and external URL values fail closed.

The proof is wired into normal CI Runtime model checks.

## Boundary result

No stop condition is triggered:

- no DOM/React/Konva per-tag renderer authority;
- no second runtime evaluator;
- no sidecar static style authority;
- no arbitrary SVG/XML editor;
- no P1.3 Visual Rule internal-target implementation;
- no SVG tag animation expansion;
- no M8 package resource weakening;
- no M9 Attribute/Property change.
