# M6.3.1.1 Canvas Hit Testing & Visual Design Space

Status: implemented on `main` · CI #390 ✅ · manual browser smoke pending.

This corrective slice follows the first M6.3.1 manual browser smoke. It fixes authoring problems exposed by real Layer interaction and separates editing-time selection priority from persisted visual z-order.

## Problems found

1. Newly created visual Layers may overlap. Normal Konva hit testing always resolves the visually topmost sibling, so a Layer explicitly selected from the left Layers panel could immediately lose selection when the same covered region was clicked on the canvas.
2. The Component Workbench artboard reused `ComponentDefinition.size.defaultWidth/defaultHeight` as its private visual design coordinate system. A small SCADA instance default such as `96 × 72` therefore also produced a tiny component-development artboard.

The second problem is an architectural coupling, not only a zoom issue. Public instance sizing constraints belong to SCADA scene usage; private component visual authoring needs its own stable coordinate space.

## Direction

```text
ComponentDefinition.size
  defaultWidth / defaultHeight
  minWidth / minHeight
        ↓
SCADA instance creation / resize constraints

ComponentVisualDefinition.designSize
        ↓
private component visual coordinate system
        ↓
Component Workbench authoring
        ↓
Composite renderer scales into an instance box
```

Design-mode selection has an additional editor-only rule:

```text
persisted sibling order
        ↓
real component z-order

selected Layer in Component Workbench
        ↓
editor-only front priority for its ancestor branch
        ↓
canvas rendering + hit testing while editing
```

Selection priority never rewrites the serialized Layer order.

## Implemented

- `ComponentVisualDefinition` is visual schema v2 and owns a private `designSize`.
- New composite visuals use an independent `480 × 360` design space.
- Existing v1 visuals migrate using the component's current default instance width/height so existing Layer coordinates keep their previous meaning.
- After migration, later changes to `ComponentDefinition.size` no longer redefine the private visual coordinate system.
- `CompositeComponentVisualRenderer` scales from `visual.designSize` into the requested render box rather than consuming public instance defaults as its source coordinate system.
- Component Workbench fits the visual design space into a large editing artboard (up to roughly `720 × 520`) instead of refusing to upscale small components.
- The canvas status distinguishes `设计空间` from `实例默认` size.
- In Design mode, the currently selected Layer is temporarily rendered at the front of its sibling stack for editing.
- If the selected Layer is nested, every ancestor on its hierarchy path is temporarily moved to the front of its own sibling stack, so the selected Layer becomes frontmost across overlapping Group branches without detaching it from its local transform hierarchy.
- This front priority is renderer-only editor state; it does not reorder `visual.layers`, change saved z-order, or create persistence changes merely by selecting a Layer.
- Preview mode does not receive the editing front priority and therefore renders the real persisted z-order.
- Canvas pointer handling now uses ordinary topmost hit testing again; the previous repeated-click hit-cycle behavior was removed because it conflicted with explicit Layers-panel selection.
- A selected Layer's transparent drag hit area renders before its own visible content and children, so selecting a Group does not mask child-layer hit testing.

## Boundaries

No change to Runtime values, bindings, behaviors, public Actions / Events / Anchors, SceneDocument, 2.5D projection, Visual Rules, Animation or Script.
