# M6.3.1.1 Canvas Hit Testing & Visual Design Space

Status: implementation in progress on `main` · CI verification pending · manual browser smoke pending.

This corrective slice follows the first M6.3.1 manual browser smoke. It fixes two authoring problems exposed by real Layer interaction.

## Problems found

1. Newly created visual Layers start in the same local position. When sibling visuals overlap, normal Konva hit testing resolves the topmost sibling, so repeatedly clicking the same overlap appears to make the last-created Layer impossible to leave.
2. The Component Workbench artboard reused `ComponentDefinition.size.defaultWidth/defaultHeight` as its private visual design coordinate system. A small SCADA instance default such as `96 × 72` therefore also produced a tiny component-development artboard.

The second problem is an architectural coupling, not only a zoom issue. Public instance sizing constraints belong to SCADA scene usage; private component visual authoring needs its own stable coordinate space.

## Direction

```text
ComponentDefinition.size
  defaultWidth / defaultHeight
  minWidth / minHeight
        ↓
SCADA instance creation / resize constraints

ComponentVisualDefinition.designSize
        ↓
private component visual coordinate system
        ↓
Component Workbench authoring
        ↓
Composite renderer scales into an instance box
```

## Intended behavior

- Component visual design size is persisted independently from public instance size.
- New composite visuals receive a large private design space.
- Existing v1 visuals migrate using the component's current default size so existing Layer geometry preserves its previous meaning.
- After migration, changing instance default/minimum size no longer changes the private visual coordinate system.
- Component Workbench fits the private visual design space into a large editing artboard even when the eventual SCADA instance is small.
- Clicking overlapping visuals can cycle through the hit Layer stack instead of permanently resolving only to the topmost sibling.
- A selected Group's transparent drag hit area must sit behind its children so it cannot mask child selection.

## Boundaries

No change to Runtime values, bindings, behaviors, public Actions / Events / Anchors, SceneDocument, 2.5D projection, Visual Rules, Animation or Script.
