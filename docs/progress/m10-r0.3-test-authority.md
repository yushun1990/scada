## Implemented

### Production code is the test subject

The old `check-m10-primitives-and-visuals.mjs` copied origin, anchor, routing,
dash, concave-rectangle and scale algorithms. Its scale fixture had already
drifted from production: it omitted the stroke-width inset used by the renderer.
It is replaced by `check-component-visual-primitives.ts`, whose name describes
its 2D scope and does not imply 3D milestone evidence.

The replacement imports routing/dash production exports and the actual
primitive drawing helpers extracted from `CompositeComponentVisualRenderer`.
Fixed expected operations verify concave paths and scale ticks/labels,
including stroke-width offsets, stretching, fixed divisions and direction.
The recording sink records draw calls; it does not calculate the expected
geometry.

`check-line-layer-interaction.ts` now imports the same geometry functions used
by `ComponentVisualCanvas` for endpoint/thickness gestures, vertex projection,
polyline normalization, two-point conversion and angle snapping. The canvas
retains event arbitration, preview/commit separation and command ownership.

### Explicit CI coverage

`.github/workflows/ci.yml` now executes the primitive/line checks and the
previously omitted controlled-script codec check. Layer-order and managed-SVG
geometry checks have explicit entries instead of relying on side-effect imports
from other tests.

`check-model-check-registration.mjs` inventories all 62 deterministic
`check-*.ts/mjs` files against CI commands and the npm scripts CI invokes.
Syntax-only `node --check` commands do not count as executed tests. A temporary
unregistered fixture was correctly rejected and then removed.

Enabling the codec check exposed a genuine failure: the visual target lookup
used `in`, admitting inherited names such as `__proto__`. The codec now uses
`Object.hasOwn`; fixtures reject inherited and unknown names for
`visual.set`, `visual.clear` and `visual.contribute`. This repairs the existing
experimental codec boundary and does not activate portable scripts.

### Documentation authority

README and PLAN now agree on the merged R0.1/R0.2 corrections, current
declarative-only portable activation, legacy draft cleanup and the remaining
R0 closeout. The current component UI design describes the actual central
work-page/right-side layer-inspector arrangement and unavailable user
Actions/Events.

The private-node execution/workspace proposal is marked `superseded`; its
method-execution suggestions are historical, not an authorized backlog. The
component-system target distinguishes deferred scripting from current
capabilities, and the Attribute/Property design's old M8 scheduling paragraph
is explicitly historical. M10 design/governance/acceptance headers record the
already-merged PR #199 baseline without promoting any implementation gate.
