## Deployed Pages proof

`scripts/pages-managed-svg-authoring-smoke.mjs` is wired into the existing post-deploy **Pages Browser Smoke** workflow.

It uses three isolated browser contexts and performs the actual user-facing flow rather than writing a synthetic visual package directly.

### Author browser

1. Open a new Component Workbench.
2. Attempt to import an SVG containing `<script>`.
3. Require a visible failure and verify the visual tree remains unchanged.
4. Import a real local nested SVG file through the normal hidden file input used by `导入 SVG / 图片`.
5. Select stable internal `svg-tag-000003`.
6. Change its `fill` from red to green through the P1.2 editor.
7. Exercise normal visual history with Ctrl+Z / Ctrl+Y and verify the field follows undo/redo.
8. Enter Preview and require green pixels on the rendered canvas.
9. Import a real PNG file through the same deployed browser ingest path.
10. Save, reopen the same component, and verify managed tag identity/value plus both self-contained assets survive reload.
11. Mark the fixture ready only after the normal authoring/save proof, then export through the normal component-package UI.

### Fresh component-import browser

1. Import the exported component package through the normal explicit file-transfer UI.
2. Require the existing confirmation gate.
3. Verify the managed SVG document/tag edit and PNG data URL persist under a new local repository identity.
4. Open a new SCADA Workbench and require the imported ready component to appear in the normal palette.
5. Place the component and require the authored green SVG visual to render on the SCADA canvas.
6. Save the Scene.
7. Export the work through the normal SCADA work-package UI.
8. Require the exported work to contain exactly one portable dependency and preserve both managed SVG + PNG self-contained resources.

### Fresh standalone browser

1. Open `#/runtime` without first initializing Studio.
2. Load the exact work artifact exported by the SCADA Workbench.
3. Require the managed SVG green visual to render on the standalone canvas.
4. Require no authoring chrome and no `scada-editor-lab` IndexedDB initialization.

This is the final deployed proof that the same authored asset survives authoring, component distribution, SCADA dependency closure and standalone rendering.
