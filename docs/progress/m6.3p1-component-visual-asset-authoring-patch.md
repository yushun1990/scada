# M6.3P1 Component Visual Asset Authoring Patch

Status: **authorized corrective patch**

## Why this is a patch, not M10

M6 accepted the Component Workbench as the advanced reusable-component authoring surface and explicitly established layered visual composition with SVG / Image / Vector / Text internals. M8 later established portable SVG/Image resource closure for component/work packages.

The remaining gap is authoring completeness:

- Component Workbench can create `svg` and `image` layers, but there is no normal file-ingest / replace workflow.
- `SvgVisualLayer` currently carries only an `assetRef`; the Workbench does not expose a safe internal SVG element/tag model.
- Visual Rules can operate on component-private visuals, but an imported SVG has no stable authoring target below the outer SVG layer.

That gap prevents normal dogfooding of real industrial SVG assets even though the model, renderer and package boundaries already claim SVG/Image visual support.

Therefore this work is M6.3P1: a corrective completion patch to the existing M6.3 visual-authoring boundary. It does **not** authorize M10 or reopen M6-M9 architecture.

## Product outcome

A component author should be able to take a local image or SVG file and turn it into an editable reusable component visual without leaving the Component Workbench.

Target workflow:

```text
local PNG/JPEG/WebP/SVG file
        ↓ import / drop
Component Workbench visual layer
        ↓
(save + reload + undo/redo)
        ↓
SVG only: inspect safe internal element tree
        ↓ select stable element/tag target
edit safe presentation fields
        ↓
optional Visual Rule target
(Attribute / Property sources remain separate)
        ↓
preview
        ↓
component package / SCADA work package
        ↓
fresh browser / standalone runtime
```

## Scope constraints

This patch is deliberately narrow.

In scope:

- local file import / drag-and-drop into Component Workbench;
- create or replace SVG/Image visual layers;
- self-contained persisted asset representation compatible with the accepted M8 resource-closure boundary;
- intrinsic size / aspect-ratio-aware initial placement;
- safe SVG parsing / sanitization;
- stable internal SVG element/tag addressing;
- an SVG structure tree in Component Workbench;
- editing a narrow safe presentation subset on supported SVG elements;
- Visual Rule targeting of stable SVG element/tag targets where the existing rule model can be extended without flattening Attribute / Property authority;
- save/reload, history, package transfer and standalone parity.

Out of scope:

- global asset manager or media-library product surface;
- remote URL fetching or hidden network dependencies;
- arbitrary HTML/DOM authoring;
- SVG `<script>`, inline event handlers, executable content or unrestricted CSS;
- `foreignObject` execution;
- a full SVG specification implementation;
- Illustrator/Figma-style vector/path point editing;
- general-purpose path authoring;
- speculative device/data integration;
- reopening Attribute binding or flattened `props`;
- a second renderer/runtime path that bypasses the existing Component Visual Runtime boundary.

## Existing authority that must be preserved

The patch starts from the current accepted model:

```text
ComponentVisualLayer
├─ group
├─ svg      { assetRef }
├─ image    { assetRef }
├─ vector
└─ text
```

Current SVG/Image rendering uses the existing Composite Component Visual Renderer. The patch must not expose raw React, DOM or `Konva.Node` objects as authored/runtime contracts.

M8 resource closure remains authoritative:

- distributable image resources are self-contained supported `data:image/...` values;
- remote/blob/relative resources cannot leak into a distributable package;
- browser import and standalone runtime remain dependency-complete and fail closed.

M9 authority remains unchanged:

```text
Attribute = authored static configuration
Property  = runtime semantic value / binding target
```

SVG presentation rules may read these two namespaces explicitly but must not merge them.

## Execution gates

### M6.3P1.0 SVG asset/tag authority freeze

**Do this first. Do not implement upload UX before this gate is settled.**

Current SVG rendering treats the whole SVG as an image resource. Internal tag editing therefore needs one canonical persisted/runtime model before UI work begins.

The gate must decide and record:

1. canonical persisted representation for imported SVG;
2. sanitization boundary and unsupported SVG behavior;
3. stable internal target identity strategy for nested `<g>`, `<path>`, `<rect>`, `<circle>`, etc.;
4. how static authoring overrides are represented;
5. how a Visual Rule addresses an SVG internal target without exposing raw DOM;
6. whether the existing renderer can consume the chosen representation efficiently or needs a controlled extension;
7. Component Visual schema/version migration implications;
8. exact interaction with M8 package resource closure.

Decision criteria:

- fidelity for representative industrial SVGs;
- stable save/reload identity;
- deterministic package serialization;
- safe/fail-closed behavior;
- no arbitrary DOM/runtime authority;
- practical runtime cost for Property-driven visual updates;
- minimal migration of existing SVG/Image packages.

Required proof fixture: one representative nested SVG containing groups and multiple independently colorable elements. The authority design must prove that two different internal targets can be addressed deterministically after save/reload and package round-trip.

Deliverable:

`docs/progress/m6.3p1.0-svg-tag-authority.md`

### M6.3P1.1 Local asset ingest + replace

After P1.0 is accepted:

- add explicit file import and drag/drop for current supported local image/SVG formats;
- importing onto empty canvas creates the correct `svg` or `image` layer;
- replacing a selected compatible layer preserves layer identity and transform unless the user explicitly requests reset;
- imported data persists in the canonical self-contained form; do not persist `blob:` URLs;
- use intrinsic dimensions/viewBox to choose sensible initial dimensions while preserving aspect ratio;
- import/replace participates in normal undo/redo and dirty/save behavior;
- malformed, unsupported or rejected assets fail visibly without mutating the current component.

Acceptance proof:

- import image → save → reload → render;
- import SVG → save → reload → render;
- replace asset → undo → redo;
- no hidden remote dependency appears in persisted state.

### M6.3P1.2 SVG structure/tag authoring

Expose a safe internal SVG structure surface in Component Workbench.

Minimum useful surface:

- hierarchical element tree for supported addressable SVG elements;
- show element type and stable target identity;
- select an element/tag target independently from the outer SVG layer;
- edit a narrow presentation subset such as `fill`, `stroke`, `strokeWidth`, `opacity` and visibility when meaningful;
- preserve structural SVG data that remains within the accepted safe subset;
- unsupported/unsafe executable features are rejected or sanitized explicitly, never silently executed.

The first patch does **not** include path point editing or arbitrary attribute editing.

Acceptance proof:

- select two different nested SVG targets;
- give them different authored fills;
- save/reload and preserve both target identities and values;
- preview matches authored state.

### M6.3P1.3 SVG target + Visual Rule integration

Extend component-private Visual Rules only as far as needed to target the safe SVG element/tag address established by P1.0.

Required behavior:

- rule activation remains Property-driven where appropriate;
- rule values may source authored Attributes or effective Properties through the existing explicit namespaces;
- rule target is a controlled visual address, not a DOM selector executed against arbitrary markup;
- missing target / missing source fails validation or evaluation according to existing fail-closed semantics;
- outer-layer Visual Rule behavior remains backward compatible.

Representative proof:

```text
Property.state = running
Attribute.runningColor = #22c55e
        ↓ private Visual Rule
SVG target indicator.fill = Attribute.runningColor
```

Element-level animation targeting is included only if P1.0 proves the current animation target abstraction can reuse the same stable visual address without introducing a new execution model. Otherwise record it as later authoring polish rather than expanding this patch.

### M6.3P1.4 Portability + deployed acceptance

Close the patch only after the real authoring path survives every already-accepted boundary it touches.

Required acceptance:

- Component Workbench save/reload;
- history behavior for asset/tag edits;
- component package export/import in a fresh browser;
- SCADA work package dependency closure;
- reusable component activation inside SCADA Workbench;
- standalone runtime rendering;
- no `blob:`, remote, relative or hidden asset dependency in distributable output;
- malformed/unsafe SVG fixtures fail closed;
- deployed GitHub Pages smoke performs an actual local-file SVG import, edits at least one internal target, saves, previews and verifies the resulting visual;
- image import has a deployed-browser smoke or equivalent deterministic browser proof.

If Component Visual schema/version changes, include migration fixtures for pre-patch SVG/Image components.

## Closeout definition

M6.3P1 is complete only when a user can build a practical component from their own SVG/Image asset through the normal UI and the result survives package/runtime boundaries without manual JSON editing.

Completion does **not** require:

- a media library;
- a full vector editor;
- arbitrary SVG scripting;
- real telemetry/device integration;
- M10.

After M6.3P1 closeout, return to the deliberate post-M9 roadmap review before authorizing new product architecture scope.
