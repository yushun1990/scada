# M6.2.13 Editor Chrome & Tabs Alignment

Status: merged · PR #77 · `15fcf378114ee5da75a31c86b3822a531c4e32fc` · final CI #365 ✅ · manual visual smoke pending.

This slice fixes visual regressions exposed by the M6.2.12 full Studio primitive migration. It stays inside the shared Studio primitive/chrome layer and does not modify editor data or runtime semantics.

## Reported regressions

1. Component Editor rendered `工作台` before `保存`, while the intended shared editor grammar is document actions first and workspace navigation at the far right.
2. Design / Preview had insufficient active-state contrast.
3. SCADA Editor left Dock tabs and right Inspector tabs were squeezed into a fraction of the available panel width.

## Root causes

### Workspace ordering

Legacy editor chrome CSS still contains `button:first-of-type` / `button:nth-of-type(...)` ordering rules from before Studio Button primitives were introduced. The portal-injected Workspace button is also a `<button>`, so those selectors could reinterpret it as a document action and override the semantic primitive ordering.

### Mode active state

Base UI Toggle exposes the pressed state, but older `.editor-header .mode-switch button` selectors have greater CSS specificity than the generic primitive active selector. The legacy transparent background therefore won even though the Toggle state was correct.

### Squeezed Tabs

The Studio `Tabs` wrapper placed its feature `className` on `Tabs.Root`. Historical `.dock-tabs` and `.inspector-tabs` classes were authored for the actual tab list and define multi-column grids. Applying them to the root made the single nested `Tabs.List` occupy only the first grid column, compressing all tabs into that fraction of the panel.

## Changes

- `Tabs` now keeps `ui-tabs` on Root and attaches feature classes to `Tabs.List`.
- Controlled `is-active` state is exposed on Studio Tab and SegmentedControl items in addition to Base UI state attributes.
- shared Dock / Inspector / Component Inspector lists use exactly three equal columns with explicit spacing.
- active Dock / Inspector tab uses the Studio accent fill and white text.
- Design / Preview active mode uses the Studio accent fill and white text so the current mode is unambiguous.
- all Studio document buttons reset legacy nth-of-type ordering.
- Workspace separator is explicitly ordered after document actions.
- Workspace action is explicitly ordered last in both editors.
- semantic Button variants override legacy `first-of-type` visual assumptions, so `primary` rather than DOM position decides the main action.

## Expected header grammar

```text
SCADA Editor
[导入] [导出] [保存]  |  [← 工作台]

Component Editor
草稿  [保存]  |  [← 工作台]
```

`工作台` is navigation and therefore remains the rightmost editor-header action in both workbenches.
