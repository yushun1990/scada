# M6.4 Animation Foundation

Status: **M6.4.1 Spin runtime + M6.4.2 Spin authoring + M6.4.3 Move + M6.4.4 Scale accepted · 2026-08-26; M6.4 remains active** on `main`.

M6.4 adds reusable private visual animation to Component Workbench without turning authored components into Konva/DOM programs.

## Goal and runtime boundary

A component developer can attach reusable animation behavior to a private visual Layer while SCADA Workbench continues to see only the component public contract.

The accepted runtime pipeline is fixed:

```text
serialized base Layer state
        ↓
Visual Rules
        ↓
effective rule-resolved Layer state
        ↓
pure Animation Evaluator(timeMs, Properties)
        ↓
transient Animation Overlay
        ↓
compose effective Layer + overlay
        ↓
CompositeComponentVisualRenderer
        ↓
Konva
```

Architectural rule:

> Animation definitions are persistent; animation frames are transient.

Animation frames never update persisted `ComponentVisualDefinition.layers`, never create per-frame undo history and never expose raw `Konva.Node`, React or DOM objects as authored animation targets. Visual Rules resolve first; animations only modulate the rule-resolved state.

## Current animation families

```text
spin        accepted · additive rotation
move        accepted · additive x/y translation
scale       accepted · multiplicative x/y scale
fade        next     · multiplicative opacity
pulse       later authoring convenience; Scale + alternate already supplies the runtime semantics
blink       later    · needs deterministic stepped visibility semantics
```

`ComponentVisualDefinition` remains visual schema v3. New animation families extend the discriminated `VisualAnimation` union and do not require a schema bump by themselves.

## Shared timing and activation

Every accepted family reuses:

```ts
type VisualAnimationTiming = {
  durationMs: number
  delayMs: number
  iterations: number | 'infinite'
  direction: 'normal' | 'reverse' | 'alternate' | 'alternate-reverse'
  easing: 'linear' | 'ease-in' | 'ease-out' | 'ease-in-out'
}

type VisualAnimationActivation =
  | { kind: 'always' }
  | {
      kind: 'property'
      propertyKey: string
      operator: VisualRuleOperator
      compareValue: ComponentScalarValue
    }
```

Property activation deliberately reuses Visual Rule condition/operator semantics rather than adding another expression language.

## Accepted overlay composition

`src/component-system/animations.ts` remains renderer-independent and imports no React or Konva API.

Current overlay channels:

```ts
type VisualAnimationLayerOverlay = {
  rotationDelta?: number
  translateX?: number
  translateY?: number
  scaleXMultiplier?: number
  scaleYMultiplier?: number
}
```

Composition semantics are locked down by deterministic CI checks:

```text
rotation deltas          add
translation deltas       add
scale multipliers        multiply
opacity multipliers      next: multiply
visibility overrides     later: deterministic stepped composition
```

Examples:

```text
Visual Rule resolved x      = 100
Move overlay                = +30
rendered x                  = 130
```

```text
Visual Rule resolved scaleX = 2
Scale overlay               = ×1.5
rendered scaleX             = 3
```

Positive Scale multipliers preserve the sign of a mirrored negative base scale.

## Validation and lifecycle

`assertComponentVisualAnimations(definition, visual)` validates:

- unique, non-empty animation IDs
- supported animation kinds
- existing Layer targets
- family-specific finite values
- positive finite duration
- non-negative finite delay
- positive integer finite iterations or `infinite`
- bounded direction/easing vocabulary
- valid Property references and typed compare values
- numeric-only relational operators

The Preview host owns `requestAnimationFrame` and elapsed epoch. The pure evaluator receives explicit `timeMs` and never reads a clock itself.

Lifecycle remains:

- Design mode never runs animation frames
- entering Preview starts at `t = 0`
- leaving Preview stops the loop and discards transient overlays
- re-entering Preview restarts at `t = 0`
- Property changes re-evaluate activation against the current Preview epoch
- animation frames never call package `onChange`

## Migration and reference reconciliation

Stored visual migration remains:

```text
v1 -> v3: restore designSize + animations: []
v2 -> v3: preserve designSize/rules/layers + animations: []
v3 -> validate directly
```

Workbench model operations preserve animation references:

- Layer rename rewrites animation targets
- Layer deletion removes orphaned animations
- clone rewrites cloned animation IDs/targets
- Group/Ungroup preserves child-targeted animations and drops removed wrapper targets
- Property rename/delete/type changes reconcile Property-activated animations

The Renderer performs none of this reconciliation.

## Renderer boundary

`CompositeComponentVisualRenderer` only receives effective visual state and draws it. It does **not**:

- parse animation definitions
- own timing/easing semantics
- inspect Property activation
- call `requestAnimationFrame`
- expose Konva nodes as authored animation targets
- persist animated values

This boundary remains important for M6.5 Controlled Script Runtime, where future `startAnimation(id)` / `stopAnimation(id)` / `restartAnimation(id)` operations must address stable animation IDs rather than renderer objects.

## M6.4.4 Scale animation family — accepted · 2026-08-26

Goal:

> Prove multiplicative scale composition as the third semantic overlay channel.

Implemented primitive:

```ts
type ScaleVisualAnimation = {
  id: string
  kind: 'scale'
  enabled: boolean
  layerId: string
  scaleXMultiplier: number
  scaleYMultiplier: number
  timing: VisualAnimationTiming
  activation: VisualAnimationActivation
}
```

Semantics:

```text
current multiplier = 1 + (target multiplier - 1) × eased progress
rendered scale      = rule-resolved scale × composed animation multiplier(s)
```

Design decisions and implementation:

- target X/Y multipliers must be finite and strictly greater than zero
- zero is rejected so animation does not collapse the transform through a singular scale
- negative target multipliers are rejected so an animation cannot unexpectedly flip coordinate orientation mid-cycle
- existing negative base scale is still supported; positive animation multipliers preserve its mirror sign
- multiple active Scale animations multiply their current multipliers
- Rules resolve `scaleX/scaleY` first, then Scale overlays multiply them
- base and rule-resolved transforms stay immutable
- Inspector has an explicit Scale branch rather than an `else == Move` assumption
- selected Layer can `+ 添加 Scale 动画`
- default Scale is `×1.2 / ×1.2 / 1000ms / infinite / normal / linear / always`

## Next slice: M6.4.5 Fade animation family

Fade should prove the fourth semantic overlay channel: multiplicative opacity.

Proposed primitive:

```ts
type FadeVisualAnimation = {
  id: string
  kind: 'fade'
  enabled: boolean
  layerId: string
  opacityMultiplier: number // 0..1
  timing: VisualAnimationTiming
  activation: VisualAnimationActivation
}
```

Proposed evaluator semantics:

```text
current opacity multiplier = 1 + (target - 1) × eased progress
rendered opacity            = rule-resolved opacity × composed fade multiplier(s)
```

Constraints:

- target multiplier is finite and in `[0, 1]`
- `0` is valid and means fully transparent at progress 1
- values greater than `1` are not needed because Layer opacity is already bounded to `[0, 1]`
- multiple Fade animations multiply
- Rules resolve opacity first; Fade overlays multiply afterward
- base opacity must never be persisted from runtime frames

`alternate` Fade can already express smooth fade-in/fade-out. A later true Blink should use explicit stepped visibility semantics rather than abusing smooth opacity interpolation.

Pulse should not be introduced as a separate runtime primitive yet: Scale with `alternate` already expresses the underlying grow/shrink behavior. A future Pulse can be an authoring preset if product UX needs it.

## Deferred / non-goals

- arbitrary keyframe/timeline editor
- CSS animation import
- arbitrary cubic-bezier strings
- spring/physics simulation
- unrestricted script callbacks
- raw Konva Tween exposure
- Web Animations API as authored contract
- per-frame persistence
- SCADA-specific animation authoring
