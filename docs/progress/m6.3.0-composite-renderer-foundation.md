# M6.3.0 Composite Renderer Foundation

Status: implemented on `main` · CI #378 ✅ · manual browser smoke pending.

This slice starts M6.3 by replacing the Component Workbench composite-artboard placeholder with the first real executor for `ComponentVisualDefinition`.

## Goal

Establish one reusable renderer boundary before adding Style, Visual Rules, Animation, Script or user-component publication.

```text
ComponentVisualDefinition
        ↓
CompositeComponentVisualRenderer
        ↓
react-konva / Konva
```

The renderer belongs to `component-system`, not to the Component Workbench page, so later SCADA publication can reuse the same visual execution path.

## Implemented

- Added `CompositeComponentVisualRenderer` under `src/component-system`.
- The renderer consumes the existing serialized `ComponentVisualDefinition` without adding a second visual model.
- Group hierarchy is reconstructed from `parentId` while preserving serialized sibling order as z-order.
- Layer-local x/y, width/height, rotation, scale, visibility and opacity are applied through nested Konva Groups.
- Root visual coordinates are scaled from the component design size into the current render size, preserving a path for resized component instances later.
- Vector layers render the existing `rect`, `circle`, `ellipse`, `line` and `path` primitives.
- Text layers render their persisted text content.
- SVG and Image layers resolve the existing `assetRef` through the browser image loader; SVG URLs remain ordinary image resources at this boundary.
- Empty or failed asset references remain visually empty instead of introducing editor-only placeholder graphics into the reusable runtime renderer.
- The Component Workbench center artboard now renders composite visuals through a real Konva Stage/Layer.
- Native built-ins remain on the trusted Native Renderer boundary and continue to show a read-only explanatory placeholder instead of reverse-engineering their internals.
- Exported the visual model and composite renderer from the component-system barrel.

## Deliberately not included

- direct canvas selection, drag, resize or rotate of private layers
- selection outlines / Transformer integration
- asset upload or asset-library persistence
- typed visual Style metadata
- Property -> Visual Rules
- animation
- controlled scripts
- publishing Workbench-authored packages into the SCADA component registry
- 2.5D or isometric scene semantics

These remain later slices. The purpose of M6.3.0 is only to make the serialized private visual tree executable through one stable renderer path.

## Architecture result

```text
Component Package
├── ComponentDefinition          public contract
└── ComponentVisualDefinition    private implementation
          ↓
CompositeComponentVisualRenderer
          ↓
Konva visual tree
```

This keeps future 2D and 2.5D-looking assets equivalent at the component boundary: an isometric SVG/PNG remains an SVG/Image layer unless a later scene-level projection capability is intentionally introduced.

## Manual browser smoke

Verify a custom composite component in Component Workbench:

- add root Vector and Text layers and confirm they appear in the center artboard
- edit x/y/width/height/rotation/scale and confirm the rendered visual follows
- hide a layer or change opacity and confirm the result updates immediately
- nest layers under a Group and confirm local transforms compose
- reorder siblings and confirm z-order changes
- set an Image `assetRef` to an existing public PNG and confirm it renders
- set an SVG `assetRef` to an existing public SVG/data URL and confirm it renders
- switch Design / Preview and confirm both modes use the same rendered visual
- reopen the saved component and confirm the same serialized tree renders again
