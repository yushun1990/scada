# M6.2.8 Component Workbench Chrome Parity

Status: merged · PR #67 · CI #341 passed · `e5f7af8e1cbac0504e89fb3dedf8a3ce6e798476` · manual visual smoke pending.

This slice continues the Component Workbench UX convergence. It changes only page chrome and canvas status placement; no Component/Scene/Runtime contract changes are introduced.

## Tracking

- PR: #67 `refactor: align component workbench chrome with scada`
- CI: #341 · Build / Lint passed
- Squash merge: `e5f7af8e1cbac0504e89fb3dedf8a3ce6e798476`

## Reported issues

- Design / Preview did not feel truly centered in the Component Editor header.
- The boxed Back button carried too much visual weight next to the product identity.
- Canvas operation/status information occupied the top of the canvas, while SCADA Editor already establishes the bottom status lane as the canonical location for this information.

## Completed in code

- Restructured Component Editor header so `mode-switch` is a direct center Grid item, matching SCADA Editor's three-column header model.
- Left identity, center mode switch and right document actions no longer depend on absolute repositioning or the width of neighboring content.
- Reworked the Back control as a quiet navigation affordance: borderless, transparent, smaller footprint, soft hover state, with explicit title/aria label.
- Status pill and Save remain grouped on the right.
- Save/error feedback moved out of the header and into the canvas bottom feedback lane using the same `canvas-toast` semantic used by SCADA Editor.
- Removed the Component Canvas status-only top toolbar from the active Component Workbench path.
- Added a Component Canvas bottom status bar using the shared `canvas-status` grammar.
- Bottom status now exposes mode, selected layer/root, layer geometry, component design size and layer count.
- Removed user-facing implementation-phase text such as `Renderer 接入 M6.3` from the canvas chrome. Milestone information belongs in progress documentation, not runtime UI.
