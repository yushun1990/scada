# M6.2.10 Studio UI Foundation

Status: implementation complete · PR pending · manual visual smoke pending.

This slice freezes the shared visual language of SCADA Studio before M6.3 functional work resumes.

## Goal

Stop solving colors, font sizes, spacing, radii and editor geometry independently inside feature CSS. Establish a small design-token layer and one final shared foundation stylesheet that governs Workspace, SCADA Editor and Component Editor.

## Product direction

SCADA Studio is a professional industrial desktop design tool:

- draw.io / Inkscape / IDE-like density
- quiet neutral chrome
- canvas-first hierarchy
- blue reserved mainly for interaction state and primary actions
- borders/surfaces before shadows
- compact but readable controls
- no card-heavy Inspector architecture

## Completed in code

- Added `src/styles/tokens.css`.
- Added `src/styles/ui-foundation.css` as the final shared style layer.
- Added normative `docs/design/ui-foundation.md`.
- `main.tsx` loads design tokens before application styles and the foundation layer after legacy/shared chrome styles.
- Shared typography now has explicit 24 / 14 / 12 / 11 / 10px tiers.
- Shared color tokens define accent, text hierarchy, neutral surfaces, canvas, borders and semantic success/warning/danger colors.
- Shared spacing scale is 4 / 6 / 8 / 12 / 16 / 24px.
- Shared radii are 4 / 6 / 8px plus pill-only 999px.
- Editor geometry is normalized around:
  - 56px Header
  - 40px Canvas Toolbar
  - 30px Canvas Status
  - 232px Left Dock
  - 336px Right Inspector
  - 28px normal controls
  - 24px small controls
  - 30px Inspector group header
- Workspace sidebar, navigation, cards/table and primary actions now inherit the same palette/typography/geometry foundation.
- SCADA Editor and Component Editor header/mode/document controls inherit the same geometry and token palette.
- Canvas toolbar, viewport controls and status lane inherit shared sizing and neutral/accent semantics.
- Inspector tabs, collapsible groups, property rows and contract controls inherit the shared compact-readable tiers.
- Component helper text is lifted out of the previous 8px micro-text tier into the 10px metadata tier.
- Existing feature CSS remains in place for local behavior/details; M6.2.10 intentionally avoids a risky full legacy stylesheet rewrite.

## Normative rule for new UI

New UI should not invent a new cross-product color, spacing value, radius, font tier or editor geometry when an existing token expresses the intent.

If a new shared primitive is genuinely required, update `docs/design/ui-foundation.md` and `src/styles/tokens.css` together.

## Architecture boundary

No changes to:

- SceneDocument
- ComponentDefinition / ComponentVisualDefinition
- persistence formats
- Registry
- Runtime / bindings / behaviors
- renderer semantics
- undo/redo

This is a presentation-system slice only.

## Manual visual smoke after merge

Verify Workspace, SCADA Editor and Component Editor together:

- typography reads as one product rather than three separate pages
- normal text remains readable despite compact density
- Header height and control height match between both editors
- Design / Preview has the same size and visual weight in both editors
- left/right dock proportions feel consistent
- Inspector remains compact but helper text is no longer excessively tiny
- toolbar/status heights are consistent
- blue is concentrated in selected/active/primary states rather than decoration
- Workspace cards/table feel visually related to editor chrome
- `工作台` navigation still aligns correctly inside the 56px Header
- no content is clipped after the 60px -> 56px Header and 32px -> 30px status normalization

After visual acceptance, treat the UI foundation as stable and resume M6.3 Composite Renderer + Visual Style / Rules without reopening global color/layout decisions unless a concrete requirement proves the foundation insufficient.
