# M6.5.9A Runtime Semantic Hardening

## Status

Implementation complete on `feat/m6-5-9a-runtime-semantic-hardening`; CI / review gate pending.

## Goal

Harden the accepted M6.5.8 compiled propagation runtime before any broad Preview integration.

This slice establishes deterministic declarative ownership and transactional Primary Device rebind semantics.

## Delivered

### Single declarative writer

A compiled SCADA DSL program now rejects multiple Value Bindings targeting the same Component Property.

This invariant is enforced in two places:

- the validated source compiler reports the ambiguity as a structural diagnostic;
- `compileScadaDslRuntime()` independently throws for an ambiguous semantic plan, preventing internal callers from bypassing the critical runtime invariant.

### Explicit derived-value invalidation

An unresolved Value Binding no longer means “keep whatever derived value happened to be there”.

Instead, runtime evaluation emits an explicit invalidation (`value: undefined`). The propagation session releases that binding's derived override, allowing the effective Component Property to fall back to the host-owned authored/default layer.

Downstream Value Bindings and Behaviors are reevaluated only when that invalidation changes the effective Property value.

### Transactional Primary Device rebind

Primary Device rebind now derives against a fresh override map rather than carrying old-device derived values forward.

The rebind transaction owns the complete runtime-local tuple:

```text
Primary Device
+ derived Component Property overrides
+ Behavior branch state
```

If propagation aborts or throws, the previously committed tuple is restored and no partial Property/Action effects escape to the host.

A successful rebind exposes only the delta between the old and new derived ownership/value state, including explicit invalidations for old overrides that the new device cannot derive.

### Validated compiler entry point

Added `compileScadaDslSource()` as the supported text-to-runtime construction path:

```text
source text
  ↓ parse
AST
  ↓ static type analysis
  ↓ semantic lowering
semantic plan
  ↓ structural validation
    - single Value Binding writer
    - no Component Property propagation cycle
  ↓
compiled runtime
```

Runtime construction occurs only after every prior phase succeeds.

## Regression coverage

Added `scripts/check-scada-dsl-hardening.ts` and wired it into CI.

Coverage includes:

- duplicate Value Binding writer rejection through the validated compiler;
- duplicate writer rejection through direct semantic-plan runtime compilation;
- cyclic derived Property graph rejection before validated runtime construction;
- missing source value releasing a derived override and falling back to base state;
- downstream derived Property + Behavior settling after invalidation;
- Primary Device rebind invalidating old-device derived values when the new device is unresolved;
- forced propagation-limit abort during rebind restoring the previous Primary Device, derived Property values and Behavior branch state atomically.

Existing M6.5.8 propagation-session and rollback checks remain in CI as compatibility regressions.

## Boundary

This slice does not connect the new DSL runtime to real Preview renderer state.

It does not define the final host-owned effective Component Property layering model beyond the runtime-local derived override semantics required here. That ownership boundary belongs to M6.5.9B.

It also does not change Scene persistence, Action/Event typing, backend deployment, QuickJS policy or legacy Scene v6 compatibility behavior.
