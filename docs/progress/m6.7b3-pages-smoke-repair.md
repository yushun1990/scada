# M6.7B3 post-B2C Pages smoke repair

Status: implementation complete on branch · deployed verification pending merge · 2026-08-29

## Failure observed

After PR #92 merged to `main`, GitHub Pages deployment succeeded, but `Pages Browser Smoke` run #174 failed in `scripts/pages-smoke.mjs` with:

```text
Persisted component <id> missing
```

The application had successfully saved the new component and navigated to its persisted component id. The smoke fixture then looked for that id in the legacy `scada-editor-lab.components.v2` localStorage value.

## Root cause

M6.6 made IndexedDB the normal component persistence authority. `localStorage` is migration input only.

The smoke script had not been migrated with the product storage model and still performed two direct legacy operations:

- seeding the animation authoring fixture through localStorage
- reading the persisted authored animation back through localStorage

This was a stale test path, not evidence that Component Workbench Save had regressed.

## Repair

`pages-smoke.mjs` now:

- opens the current `scada-editor-lab` IndexedDB database at schema v2
- reads the saved component record from the `components` object store
- parses and updates the repository record's serialized `document`
- writes the fixture back through the same object store
- reads persisted authored animation state back from IndexedDB
- waits for the UI's `组件已保存` success state before persistence-sensitive assertions on saves that do not navigate to a new id

The repair intentionally does not reintroduce active localStorage persistence.

## Acceptance

Normal PR CI must pass before merge.

After merge, the GitHub Pages deployment and `Pages Browser Smoke` must run against the deployed revision. M6.7B3 should not be marked accepted in `PLAN.md` until that deployed smoke passes again.
