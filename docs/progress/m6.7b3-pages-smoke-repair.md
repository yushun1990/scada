# M6.7B3 post-B2C Pages smoke repair

Status: accepted · deployed Pages smoke restored · 2026-08-30

## Failure sequence

After PR #92 merged, GitHub Pages deployed successfully but the deployed-browser suite exposed test fixtures that still treated legacy localStorage as active persistence even though M6.6 had moved normal authoring to IndexedDB.

The failures were test-harness migration debt, not evidence that the application had reverted to localStorage.

## Repairs

### PR #93

Migrated the primary `pages-smoke.mjs` component fixture to the current IndexedDB `components` store and waited for asynchronous Component Save completion.

The next deployed run proved that repair and then exposed the same stale assumption in a separate animation smoke.

### PR #94

Added one shared Pages-smoke IndexedDB component fixture helper and migrated:

- Move
- Scale
- Fade
- Blink

The post-merge deployed run then passed the primary component smoke, all four animation smokes, and Chromium/Firefox pointer smokes. Only the final SCADA geometry smoke remained stale.

### PR #95

Added the Scene fixture equivalent for the IndexedDB `scenes` store and migrated `pages-scada-geometry-smoke.mjs` away from `scada-editor-lab.work.<id>.scene.v4` localStorage.

The geometry smoke now waits for the Scene repository record's `updatedAt` to change after Save before making persistence-sensitive assertions.

The deployed Pages smoke is restored and aligned with the current persistence architecture.

This provides the final deployed-browser evidence required to close M6.7B3 with the recorded **defer production deployment** decision.
