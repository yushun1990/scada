# M6.3.4 Component Canvas Authoring Commands

Status: **implementation complete, manual browser smoke pending** on `main`.

This slice brings Component Workbench canvas editing closer to the SCADA Workbench interaction grammar without copying scene-only behavior into component development.

## Product decision

Component Workbench uses the same authoring command families where the concepts are genuinely shared:

```text
Snap
Align
Distribute
Group / Ungroup
```

Those commands are built on the component-Layer selection model rather than by cloning SCADA scene behavior around different data structures.

## Interaction invariants

- Canvas commands live in the Canvas Toolbar above the component canvas.
- Header owns document-level operations and Design/Preview mode only.
- Dragging follows the pointer directly.
- Alignment/snap guides may appear during drag, but they do not modify position.
- Actual grid/object snapping happens once on `dragend`.
- Grid display and snap enable state are independent.
- Resize/rotate snapping is deferred until movement authoring is accepted.

## Completed implementation

### Component snap

- component-private `designSize` uses a 24-unit design grid
- snap toggle defaults on
- object snapping compares sibling Layer left/center/right and top/center/bottom anchors
- grid/object candidates use a screen-pixel threshold so zoom does not change perceived snap sensitivity
- nested Layer correction is converted back through the parent transform before persistence
- drag-time guides are hints only
- final snap applies on mouse release

### Canvas Toolbar ownership

The snap, hierarchy and geometry controls are owned by `ComponentEditorPage` and rendered in the formal Canvas Toolbar above `ComponentVisualCanvas`.

`ComponentVisualCanvas` remains responsible for canvas rendering and pointer interaction.

### M6.3.4.1 Layer multi-selection

The editor owns one shared selection model:

```text
selectedLayerIds: readonly string[]
primaryLayerId: string | null
```

Implemented behavior:

- click selects one Layer
- Shift/Ctrl/Meta-click toggles membership
- Layers panel and canvas share the same selection state
- component-root selection clears Layer selection
- the last explicitly selected Layer becomes primary
- single-Layer Inspector editing is exposed only when exactly one Layer is selected
- multi-selection keeps primary context without exposing accidental single-Layer Inspector mutation
- Preview cannot mutate geometry

### M6.3.4.2 Shared geometry command core

Renderer/model-independent geometry commands live in `src/geometry/commands.ts`:

```text
alignLeft
alignCenterX
alignRight
alignTop
alignCenterY
alignBottom
distributeHorizontal
distributeVertical
```

The shared core consumes only simple bounds and returns translation deltas. It does not depend on `SceneNode`, `ComponentVisualLayer`, React or Konva.

Adapters own model-specific translation:

- SCADA converts Scene world/local transforms around shared deltas.
- Component Workbench computes Layer world bounds from parent transforms and converts deltas back into Layer-local `x/y`.
- nested component selections collapse to outermost selected Layers for geometry commands so selecting a parent and its descendant cannot double-translate the descendant.

### M6.3.4.3 Align / Distribute toolbar commands

The Component Canvas Toolbar exposes the same six alignment and two distribution commands as SCADA Workbench.

Enable rules use effective geometry targets:

```text
1 target selected    -> Align disabled / Distribute disabled
2+ targets selected  -> Align enabled
3+ targets selected  -> Distribute enabled
```

Preview/read-only mode disables geometry commands.

### M6.3.4.4 Group / Ungroup

Safe scope implemented:

```text
2+ selected sibling Layers -> Group
1 selected Group            -> Ungroup
```

Behavior:

- cross-parent Group is disabled
- Group receives a fresh deterministic `groupN` id; existing child ids remain stable
- selected sibling order remains deterministic in the flat Layer store
- child transforms are shifted into the new Group coordinate system without changing world appearance
- Group becomes the selection after grouping
- direct children become the selection after ungrouping
- rules targeting existing child ids remain intact; a rule targeting a removed Group is reconciled normally
- Group visibility/opacity is folded into direct children during Ungroup
- Ungroup composes Group and child transforms before reparenting
- if non-uniform Group scaling combined with child rotation creates skew that `VisualLayerTransform` cannot represent, Ungroup refuses the operation instead of silently distorting geometry

## Acceptance gate

M6.3.4 is complete only when manual browser smoke confirms:

- snap toggle is in the formal Canvas Toolbar above the canvas
- drag remains unsnapped until release
- canvas and Layers panel share multi-selection
- all six align commands work for 2+ selected Layers
- horizontal/vertical distribution works for 3+ selected Layers
- Group/Ungroup preserves appearance and ids
- save/reopen preserves transforms and hierarchy
- Preview disables geometry commands
- shared geometry extraction does not regress SCADA Workbench behavior
