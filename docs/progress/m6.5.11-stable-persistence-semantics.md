# M6.5.11 Stable persistence semantics

Status: implementation complete / acceptance gate

Date: 2026-08-28

## Goal

Turn the accepted SCADA Value Binding / Behavior / Interaction semantics into a long-term Scene persistence contract without treating DSL source text or one compile session's statement positions as persisted identity.

## Accepted persistence boundary

The authoring flow remains:

```text
DSL source
    ↓ parse / lower / static analysis
validated semantic plan
    ↓ persistence canonicalization
PersistedScadaSemantics v1
    ↓ Scene v7
local / future repository persistence
```

The persisted representation is structured semantic data, not DSL source text.

The runtime restoration flow is:

```text
Scene v7 PersistedScadaSemantics
    ↓ structural validation
restoreScadaSemanticPlan
    ↓
compileScadaDslRuntime
```

Restoring a saved Scene does not require reparsing the original DSL text.

## Stable identity

Lowering IDs such as:

```text
value:0
behavior:3
interaction:5
```

are intentionally compile-session identities only. They may change when unrelated source statements move.

Persistence replaces those IDs with deterministic semantic identities derived from canonical structured content. Therefore an unchanged Value Binding, Behavior or Interaction retains the same persisted ID when unrelated DSL statements are reordered.

Semantically identical duplicates receive an occurrence suffix only to keep persisted IDs unique.

## Canonical references

Authoring symbols are resolved before persistence.

Examples:

```text
device.pressure
```

persists as a primary-device-relative property reference rather than as the authoring symbol `device`.

```text
outlet.level
```

persists using the resolved explicit `sourceId`, not the temporary DSL symbol `outlet`.

The same rule applies to Device/Platform Action targets.

This keeps the stored Scene contract independent of authoring aliases.

## Scene v7

Scene schema advances from v6 to v7 because there is now a real new persisted contract:

```text
ComponentSceneNode
├─ props
├─ bindings          legacy v5 compatibility-only
├─ behaviors         legacy v6 compatibility-only
└─ scadaSemantics    v7 canonical SCADA semantics or null
```

New component nodes explicitly start with `scadaSemantics: null`.

When v1-v6 Scene JSON is loaded, the existing legacy bindings/behaviors are preserved and the component receives `scadaSemantics: null` in the normalized v7 document.

Legacy Scene v6 Event -> Component Action behavior remains compatibility-only. It is not converted into the new semantic model automatically because doing so would invent semantics that were not authored under the new contract.

## Validation and corruption handling

Persisted semantics validation rejects:

- unsupported persisted-semantics versions
- malformed expression/reference shapes
- duplicate persisted IDs
- duplicate declarative Value Binding writers
- Component Property dependency cycles
- persisted Component Property references that no longer exist on the component contract
- persisted Component Actions that no longer exist or violate declared arity
- persisted Component Events that no longer exist

This moves corrupt/stale persisted semantics failure to Scene load/validation rather than allowing invalid state to reach Preview execution.

## Save normalization

The local save path now serializes through the current Scene parser/migrator rather than calling `JSON.stringify(scene)` directly.

This prevents a legacy-v6 in-memory fixture/document from being written back as a legacy long-term format accidentally.

The existing localStorage repository mechanism itself is deliberately unchanged at this gate. Storage abstraction and IndexedDB belong to M6.6.

## Regression coverage

`scripts/check-scada-semantics-persistence.ts` covers:

- stable persisted IDs under unrelated DSL statement reordering
- canonical primary-device and explicit-source references
- JSON round-trip
- restoring a semantic plan and compiled runtime without DSL reparsing
- duplicate writer rejection
- Component Property cycle rejection
- duplicate persisted ID rejection

The existing full application Build additionally verifies Scene v7 model/parser integration with the browser product path.

## Non-goals

M6.5.11 does not add:

- DSL source-text persistence as runtime authority
- IndexedDB
- repository interfaces
- debug snapshot export/import
- backend persistence
- production device adapters
- general-purpose scripting
- Event payload expression scope

Those boundaries remain intentionally separate.

## Next gate

After M6.5.11 acceptance, proceed to **M6.6 Local persistence foundation**:

```text
Workbench features
    ↓
Repository interfaces
    ├─ IndexedDB production implementation
    └─ Memory deterministic-test implementation
```

M6.6 should own localStorage migration, versioned database schema, deterministic storage migration tests, debug snapshot export/import/reset and storage diagnostics.
