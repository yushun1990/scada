## Gate

This slice implements only **M6.3P1.3 SVG target + Visual Rule integration** on top of accepted P1.0–P1.2 authority.

It does not add SVG-tag animation, a second renderer/evaluator, arbitrary selectors, or any M8/M9 authority change.

## Controlled visual address

Visual Rule carries one optional private SVG address:

```text
layerId
svgTagId?      optional
目标字段
```

The address is exactly the P1.0 frozen authority:

```text
(layerId, svgTagId?)
```

It is not a DOM selector, XPath, source SVG `id`, React ref or Konva node id.

When `svgTagId` is absent, all existing whole-layer Visual Rule behavior is unchanged.

When `svgTagId` is present:

- `layerId` must resolve to a managed SVG layer;
- `svgTagId` must resolve to one retained presentation-editable managed element;
- the target is limited to `fill`, `stroke`, `stroke-width`, `opacity` through the existing Visual Rule target vocabulary;
- missing/unmanaged/unsupported targets fail validation.

## Runtime authority

The existing Visual Rule evaluator remains the only evaluator:

```text
Property condition
    ↓
existing resolveComponentVisualRules()
    ↓
(layerId, svgTagId?) + controlled target
    ↓
resolved ComponentVisualDefinition snapshot
    ↓
existing animation overlay
    ↓
CompositeComponentVisualRenderer
    ↓
managed document serializer
    ↓
existing Image / Konva.Image path
```

A matching SVG-tag rule mutates only the **resolved in-memory managed document snapshot**.

It deliberately does not rewrite the persisted base `assetRef`. The authored base invariant therefore remains owned by the persisted component:

```text
base assetRef == serializeManagedSvgDataUrl(authored document)
```

while runtime rendering derives the image source from the resolved document snapshot.

## Attribute / Property authority

M9 remains unchanged.

Visual Rule conditions remain Property-driven.

Target values may use:

- a literal;
- explicit `valueSource.namespace = attribute`;
- explicit `valueSource.namespace = property`.

The Workbench editor exposes this distinction instead of flattening values into one props namespace.

Representative accepted shape:

```text
Property.state == running
        ↓
(layerId = svg1, svgTagId = svg-tag-000005, target = style.fill)
        ↓
Attribute.runningColor
```

## Workbench authoring

For a selected managed SVG layer, each Visual Rule can choose its action scope:

- entire outer Layer;
- one retained presentation-editable `svg-tag-*` target.

Switching scope resets the target/value to a valid baseline and clears an incompatible previous value source.

For target values, the editor exposes:

- Literal;
- Attribute;
- Property.

Only source definitions whose default values are compatible with the selected target are offered.

Existing non-SVG Layer rules keep the current UI/behavior.

## Structural replacement fence

A full SVG file replacement creates a new managed document and therefore a new structural identity domain.

To avoid accidentally retargeting a rule merely because the replacement happens to contain the same preorder number, replacement fails closed while the selected SVG layer still has internal-tag Visual Rules.

The author must first delete or retarget those rules to the whole Layer, then replace the file explicitly.

This is intentionally safer than guessing logical identity across unrelated SVG documents.

## Validation / deterministic proof

`scripts/check-managed-svg-visual-rules.ts` proves:

- Property conditions can target a stable nested private tag;
- target fill can source an authored Attribute through the explicit namespace;
- unmatched conditions preserve authored tag/layer values;
- matching rules update only the resolved document snapshot;
- authored base document remains immutable;
- persisted base `assetRef` is not rewritten by runtime rule evaluation;
- legacy whole-layer rules continue to resolve in the same pipeline;
- missing SVG tags fail validation;
- layer-only targets such as transforms are rejected for SVG-tag scope;
- unsafe SVG presentation values fail closed;
- structural SVG replacement is blocked while tag rules exist;
- package v2 round-trip preserves optional `svgTagId` and explicit `valueSource`.
