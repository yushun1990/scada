# M6.3.2 Typed Visual Style

Status: implemented on `main` · CI #395 ✅ · manual browser smoke pending.

This slice establishes renderer-independent typed visual Style as the stable target surface for later property-driven Visual Rules.

## Goal

Keep visual appearance in serialized component-private data instead of hard-coding it inside the Konva renderer.

```text
ComponentVisualLayer.style
        ↓
CompositeComponentVisualRenderer
        ↓
Design / Preview

later:
Component Property / internal value
        ↓
Visual Rule
        ↓
Layer style target
```

## Implemented

- Extended visual schema v2 with backward-compatible optional typed Style fields; no package migration or visual version bump is required.
- Absence of an explicit Style resolves through canonical defaults, preserving the appearance of existing components.
- Vector Style now owns fill, stroke and stroke width.
- Text Style now owns fill, font family, font size, font style, horizontal alignment, vertical alignment and line height.
- SVG/Image Style now owns asset fit mode: stretch, contain or cover.
- Visual validation checks explicit Style values while continuing to accept older v2 Layers without Style.
- Visual cloning deep-copies explicit Style so editor/package state does not share mutable style objects.
- Composite renderer no longer hard-codes Vector and Text appearance; it resolves typed Layer Style.
- Asset renderer implements stretch / contain / cover without changing component-private geometry.
- Added contextual Style groups to the Component Workbench selected-Layer Properties inspector.
- Style edits use the same `ComponentVisualDefinition` authoring path as geometry and are persisted by the existing package save path.
- Group has no synthetic paint Style in this slice; visibility/opacity/transform remain its relevant visual controls.

## Compatibility rule

Visual schema remains version 2 deliberately:

```text
style absent
  -> canonical renderer default

style present
  -> validate + persist + render explicit values
```

This keeps existing saved components valid while giving the next Visual Rules slice stable typed targets such as:

```text
vector.style.fill
vector.style.stroke
text.style.fill
text.style.fontSize
asset.style.fit
```

## Boundaries

Not included yet:

- Property -> Visual Rules
- conditional expressions
- shadow / filter effects
- gradients
- animation
- scripts
- asset upload/library persistence
- user component publication into the SCADA registry
- 2.5D scene projection
