# M6.2.7 Compact Property Contract Summary / Detail

Status: implementation complete · PR pending · manual visual smoke pending.

This slice follows the Component Workbench interaction convergence and M6.2.5 compact Inspector density. It changes only public Property authoring presentation; `ComponentDefinition.properties` remains the same public contract.

## Goal

Stop rendering every public Property as a permanently expanded form. The default view should answer “what public Properties does this component expose?” at a glance, while detailed editing remains one click away.

```text
▾ Public Properties
speed      number      1200       bindable  ›
state      select      normal · 4  bindable  ›
alarm      boolean     off                   ›
color      color       ■ #ef4444   bindable  ›

click one row
        ↓
inline detail editor for that Property only
```

## Completed in code

- Added `ComponentPropertyContractEditor` dedicated to compact public Property authoring.
- Public Properties now render as dense summary rows by default instead of one expanded card/form per Property.
- A summary dynamically exposes Property title/key, kind, default value and bindable state.
- Color Properties include a compact color swatch.
- Select Properties show the current default option plus option count.
- Boolean Properties summarize the default as on/off instead of rendering a checkbox until detail mode.
- Clicking a summary toggles its inline detail editor.
- At most one Property detail editor is expanded at a time.
- Adding a Property immediately expands the new item so authoring can continue without another search/click.
- Renaming a Property keeps the detail editor attached to the new key.
- Removing the expanded Property closes the detail state.
- Read-only / Preview mode still allows summary/detail inspection while keeping all authoring controls disabled.
- Detailed editing preserves the existing fields: key, title, kind, typed default, select options, bindable and description.
- Added dedicated compact styles without changing the shared Inspector group semantics.

## Architecture boundary

No changes to:

- `ComponentDefinition` schema
- Property kinds/default semantics
- Scene model
- Runtime bindings
- Action/Event behavior
- Component Registry
- persistence format
- undo/redo semantics

The existing `ComponentContractEditor` remains responsible for Actions / Events / Anchors. This slice deliberately does not widen the refactor to those contract families yet, although the summary/detail interaction can be reused later.

## Manual visual smoke after merge

Verify in Component Workbench:

- a component with several public Properties shows one compact row per Property
- the list remains readable at the current right-panel width
- title/key, kind, default and bindable state are understandable without opening details
- string/number/boolean/color/select summaries all express their defaults sensibly
- clicking one row opens only that Property detail
- clicking another row closes the previous detail and opens the new one
- adding a Property creates and opens its detail editor
- renaming the key keeps the edited Property open
- deleting a Property removes it and closes its detail editor
- all existing Property fields still save/reopen correctly
- Preview/read-only mode allows inspection but not mutation

After acceptance, evaluate whether the same summary/detail primitive should be applied to Actions / Events / Anchors before or during the next Component Workbench UX slice. M6.3 Composite Renderer + Visual Style / Rules remains the next functional milestone.
