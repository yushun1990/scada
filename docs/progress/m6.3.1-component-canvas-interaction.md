# M6.3.1 Component Canvas Interaction

Status: implemented on `main` · CI checkpoint running · manual browser smoke pending.

This slice turns the M6.3.0 composite renderer from a read-only visual executor into the first direct-manipulation surface for private component layers.

## Goal

Keep one serialized `ComponentVisualDefinition` as the source of truth while allowing the Component Workbench canvas to edit layer transforms directly.

```text
Layer Tree / Inspector
        ↕
ComponentVisualDefinition
        ↕
Composite Renderer
        ↕
Canvas selection + Transformer
```

No editor-only geometry model is introduced.

## Implemented

- Composite visual layer Groups now expose stable Konva node identity derived from the existing Layer id.
- Canvas pointer selection resolves the nearest private visual Layer and synchronizes the existing Workbench selection state.
- Clicking blank artboard space returns selection to the component root.
- The selected visible Layer receives a Konva Transformer in Design mode.
- Selected Layers can be dragged, resized through scale handles, and rotated directly on the component artboard.
- Drag / transform completion writes x, y, rotation, scaleX and scaleY back into the selected Layer's serialized transform.
- Existing width / height remain the Layer's intrinsic design dimensions; Transformer resizing composes through scale rather than rewriting Group dimensions, preserving correct behavior for nested Group children.
- The same `onChange` path used by the Inspector receives canvas edits, so save/reopen continues to persist one visual tree rather than a canvas-only shadow state.
- Only the selected Layer is draggable; other layers remain listening for selection without creating competing nested drag owners.
- A transparent hit area is added only for the selected Layer so a selected Group can be dragged even when its visible content is made entirely from children.
- Preview mode and built-in Native visuals remain non-editable and do not expose Transformer controls.

## Architecture boundary

No changes to:

- `ComponentDefinition`
- SceneDocument
- Runtime values / bindings / behaviors
- public Actions / Events / Anchors
- user component publication
- Style / Rules / Animation / Script
- 2.5D / isometric scene semantics

Canvas interaction is an authoring adapter over `ComponentVisualDefinition`; the reusable Composite Renderer still remains the visual execution boundary.

## Manual browser smoke

Verify a custom composite component:

- click a visible Layer on the artboard and confirm the left Layer Tree and right Inspector select the same Layer
- click blank artboard space and confirm selection returns to the component root
- drag the selected Layer and confirm Inspector X/Y update after drag end
- resize from Transformer handles and confirm Scale X/Y update
- rotate and confirm rotation updates
- select a Group in the Layer Tree, drag it, and confirm its complete child subtree moves visually together
- hide the selected Layer and confirm the Transformer disappears
- switch to Preview and confirm direct manipulation and Transformer controls disappear
- return to Design and confirm selection/editing resumes
- save and reopen the component and confirm transform edits persist
