# M6.3P1 SVG import compatibility regression

Status: **dogfooding corrective patch · 2026-09-05**

## Trigger

Immediately after M6.3P1 closeout, real local SVG assets failed to import with errors such as:

```text
SVG 包含不支持的元素 <style>
```

and related failures from common editor/export metadata.

The deployed M6.3P1 acceptance fixture was intentionally small and hand-authored. It proved managed SVG authority, stable tag identity, tag authoring, portability and standalone parity, but it did not prove representative compatibility with common Illustrator/Inkscape/material-library SVG export patterns.

The defect therefore does not invalidate the renderer/runtime authority decisions, but it does invalidate the practical product assumption that the current safe subset was broad enough for normal dogfooding.

## Root cause

`src/component-system/managedSvg.ts` is a fail-closed canonical parser with an explicit retained element/attribute subset.

That parser correctly rejects executable and external-resource behavior, but common SVG exports frequently encode static presentation as:

```xml
<style>
  .st0 { fill: #22c55e; stroke: #0f172a; }
</style>
<path class="st0" ... />
```

The canonical managed model deliberately does not persist unrestricted CSS or `class` selector authority. Before this patch, however, the import path attempted to feed this source directly into the canonical parser, so `<style>` itself failed before its static presentation could be normalized into the already-authorized attributes.

Inkscape/Sodipodi non-rendering metadata can produce the same practical failure even though it is not part of the rendered asset.

## Corrective boundary

This patch adds a **transient import compatibility normalization pass** before the existing canonical managed SVG parser.

```text
local SVG source
    ↓ compatibility normalization (transient)
static safe stylesheet/class expansion
known non-rendering editor metadata removal
    ↓
existing parseManagedSvgSource()
    ↓ final fail-closed canonical validation
ManagedSvgDocument
    ↓
existing serializer / visual rules / renderer / M8 closure
```

The compatibility pass is not persisted and is not runtime authority.

`ManagedSvgDocument` remains the only persisted internal SVG authority. `assetRef` remains its deterministic derivative. The Composite renderer, Visual Rule evaluator, M8 resource closure and M9 Attribute/Property separation are unchanged.

## Supported compatibility expansion

The first corrective slice supports static stylesheet rules using simple selectors:

- element selector (`path`)
- class selector (`.st0`)
- id selector (`#lamp`)
- simple combinations such as `path.st0`
- comma-separated selector lists

Only the same safe presentation property family already accepted by managed SVG inline-style normalization is allowed. Stylesheet declarations are expanded to transient inline style, after which the canonical parser normalizes them into managed attributes.

Known non-rendering compatibility metadata is discarded before canonical parsing:

- SVG `<metadata>` subtrees
- Inkscape namespace elements/attributes
- Sodipodi namespace elements/attributes
- `class` after stylesheet expansion
- non-rendering `data-*`, `aria-*`, `role`, `focusable`, `tabindex` compatibility metadata

## Still fail-closed

This patch intentionally continues to reject:

- `script`, event handlers and executable SVG behavior;
- DTD/entity input and unsupported processing instructions;
- external HTTP/file/blob resources;
- CSS `@import`, `@font-face`, `@media`, keyframes and other at-rules;
- complex selectors requiring descendant/sibling/pseudo-selector runtime semantics;
- unsupported presentation declarations;
- unsupported visible SVG structures that are not yet represented by the canonical managed SVG model.

A future compatibility expansion must continue to normalize into the same canonical managed document rather than retain a second CSS/DOM authority.

## Acceptance guard

`scripts/pages-svg-import-compatibility-smoke.mjs` adds a deployed-browser fixture modeled on common editor output:

- `<style>` using class and id selectors;
- a class-driven fill/stroke/stroke-width;
- id-driven opacity;
- Inkscape label metadata;
- Sodipodi named-view metadata;
- an unsafe stylesheet with an external URL that must still fail closed.

The smoke verifies the safe asset imports as a managed SVG and exposes the normalized presentation values through the existing tag editor.

This is a post-closeout corrective defect, not a new milestone and not authorization to reopen M8/M9 or introduce another renderer/runtime path.
