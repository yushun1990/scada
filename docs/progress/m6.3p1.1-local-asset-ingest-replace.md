# M6.3P1.1 Local asset ingest + replace

Status: **implementation complete on branch · acceptance pending**

## Scope

This slice implements the local file-ingest boundary authorized only after M6.3P1.0 was merged.

It does not implement SVG internal structure/tag authoring UI (P1.2) or internal-tag Visual Rule targeting (P1.3).

## Accepted authority carried forward

The implementation preserves the P1.0 model:

```text
SvgVisualLayer
├─ document?   canonical managed SVG authority
├─ assetRef    deterministic data:image/svg+xml derivative when managed
├─ transform
├─ visible / opacity
└─ style.fit
        ↓
existing CompositeComponentVisualRenderer
        ↓
existing Image / Konva execution path
```

Legacy SVG layers may remain opaque `assetRef` resources without `document`.

No DOM node, React element or `Konva.Node` becomes persisted/runtime authority.

## Implementation

### Component Visual v4

`COMPONENT_VISUAL_VERSION` advances from 3 to 4 only to encode the optional managed SVG document.

- v3 visuals migrate to v4 without reparsing SVG resources;
- existing SVG layers therefore remain opaque after migration;
- only an explicit local SVG import/replace creates a managed document;
- a managed layer is invalid if its persisted `assetRef` differs from the canonical serialization of its `document`.

This prevents document/assetRef dual authority.

### Managed SVG ingest

`src/component-system/managedSvg.ts` owns the safe import/serialization boundary.

Imported SVG is parsed into the private structured document frozen in P1.0 and receives deterministic preorder tag identities:

```text
svg-tag-000001
svg-tag-000002
...
```

The importer is deliberately fail-closed. It rejects executable/unsafe or unsupported structures instead of executing or silently preserving them, including script/event handlers, DTD/entity input, unsupported elements/attributes and external resource references.

Inline presentation style is normalized into the same allowlisted structured attributes rather than retained as unrestricted CSS.

### Local image ingest

The normal Workbench file flow supports:

- SVG
- PNG
- JPEG
- WebP

Raster assets are read directly as `data:image/...` values. No `blob:` URL is persisted.

SVG is serialized directly to the canonical self-contained `data:image/svg+xml` form.

Therefore a normally imported asset is already compatible with the accepted M8 distributable visual-resource closure.

### Initial placement

A newly imported asset uses its intrinsic dimensions/viewBox and is centered in the Component Visual design space.

If necessary it scales down to fit within 80% of the visual design size while retaining aspect ratio; small assets are not enlarged automatically.

### Replacement

When the selected layer is a compatible SVG/Image layer, importing the same resource kind replaces the asset while preserving:

- layer ID;
- name;
- parent;
- transform;
- visibility / opacity;
- existing asset style.

The explicit selected-layer replacement control rejects incompatible file kinds before `onChange`, so the current visual remains unchanged on failure.

### Workbench UI

Component Workbench now exposes:

- `导入 SVG / 图片` in the visual layer area;
- drag/drop into the same ordinary DOM import zone;
- `替换文件` for a selected SVG/Image layer;
- visible success/error feedback.

The import/drop/replace path calls the same `onChange(ComponentVisualDefinition)` authority as all other visual edits.

The existing Component Visual canvas history observes this same visual state and already owns the 100-step undo/redo stack. No second asset-history mechanism is introduced.

### Renderer

For a managed SVG the existing Composite renderer derives the image source from the canonical document before calling the existing `Image` / `Konva.Image` path.

This is a controlled extension of the same renderer, not a second SVG renderer.

### Distribution compatibility

The distributable component package remains version 2.

Its parser now applies the shared Component Visual migration before current validation, so a package-v2 artifact carrying a legacy visual-v3 snapshot can normalize to visual v4 without inventing a second package version.

M8 resource closure remains unchanged: SVG/Image assets crossing the distributable boundary must still be self-contained supported `data:image/...` references.

## Deterministic proof

`scripts/check-managed-svg-assets.ts` proves:

- nested managed SVG tag identity serializes deterministically;
- two independently addressable nested targets retain distinct stable IDs;
- managed `document` and derived `assetRef` cannot diverge;
- new asset placement preserves intrinsic aspect ratio;
- compatible replacement preserves layer identity and transform;
- incompatible replacement fails without mutating the current visual;
- visual v3 migrates to v4 as opaque SVG rather than being silently reparsed;
- managed SVG survives distributable package round-trip;
- package v2 can normalize legacy visual v3 through the shared visual migration.

The check is wired into normal CI runtime/model checks.

## Boundary result

No stop condition is triggered:

- no second renderer/runtime authority is introduced;
- M8 package/resource authority is not weakened;
- M9 Attribute/Property authority is untouched;
- SVG internal tree editing is not exposed early;
- SVG internal Visual Rule targeting is not implemented early.
