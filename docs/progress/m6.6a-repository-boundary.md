# M6.6A Local repository boundary

Status: accepted

Date: 2026-08-28

## Goal

Stabilize the storage-facing contracts before replacing the browser's existing localStorage implementation with IndexedDB.

M6.6 is intentionally split so repository semantics are not designed at the same time as React asynchronous loading behavior and browser migration code.

## Repository contract

The accepted direction is asynchronous from the beginning:

```text
SCADA Works / Component Library
        ↓
SceneRepository / ComponentRepository
        ↓
physical storage implementation
```

Both repositories expose:

- `list`
- `get`
- `put`
- `delete`
- `replaceAll`
- `clear`

Records contain:

```text
id
updatedAt
document   canonical JSON string owned by the domain codec
```

The repository layer stores documents; it does not become the Scene or Component semantic validator.

## Why async now

IndexedDB is asynchronous. A synchronous repository API would either have to be replaced in M6.6B or hide an unsafe fire-and-forget persistence layer behind a synchronous facade.

The contract therefore becomes async before the product is wired to it.

This gate deliberately leaves current feature-level localStorage as the active browser path until M6.6B updates the application lifecycle.

## Memory repositories

`MemorySceneRepository` and `MemoryComponentRepository` provide the deterministic test implementation required by the roadmap.

They guarantee:

- cloned read/write boundaries
- deterministic ID ordering
- duplicate-ID rejection before `replaceAll` mutation
- independent focused repository use
- the same asynchronous public API intended for IndexedDB

## Debug snapshot foundation

Debug snapshot schema v1 is introduced before browser storage migration:

```json
{
  "schemaVersion": 1,
  "scenes": [],
  "components": []
}
```

Repository `document` strings are exported as structured JSON values so support snapshots remain readable and portable rather than containing nested escaped JSON strings.

The codec validates:

- supported schema version
- unique record IDs per collection
- JSON-compatible values only
- valid repository JSON during export

Import validates the complete snapshot before either logical collection is replaced.

IndexedDB will provide the physical transaction boundary in M6.6B.

## Regression coverage

`scripts/check-storage-repositories.ts` covers:

- deterministic Memory repository ordering
- clone/isolation semantics
- rejected duplicate `replaceAll` without state corruption
- debug snapshot export/import round-trip
- deterministic snapshot ordering
- malformed and duplicate snapshot rejection before mutation
- corrupt repository JSON rejection
- reset behavior
- focused `get` / `put` / `delete`

## Boundary

M6.6A does **not** switch the product away from localStorage yet.

It does not yet add:

- IndexedDB implementation
- localStorage -> IndexedDB migration
- React async load/save integration
- browser storage diagnostics UI
- final atomic IndexedDB snapshot import transaction

Those are M6.6B.

## Next gate

M6.6B should:

1. implement the same repository interfaces on one versioned IndexedDB database
2. migrate supported SCADA Works and custom Component Library localStorage data once
3. wire Workspace, SCADA Editor and Component Editor to async repository-backed services
4. make debug snapshot import/reset physically transactional where IndexedDB permits
5. expose storage diagnostics suitable for browser bug reports
6. add deterministic migration fixtures and browser-facing smoke coverage where needed
