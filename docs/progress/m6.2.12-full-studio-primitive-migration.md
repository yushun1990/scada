# M6.2.12 Full Studio Primitive Migration

Status: implementation complete · PR #75 open · CI #359 Build / Lint / primitive audit passed · manual visual smoke pending.

This slice closes the staged-migration loophole left by M6.2.11. The goal is not merely to make common controls available under `src/ui`, but to make the Studio primitive layer the mandatory control boundary for Workspace, SCADA Editor and Component Editor.

## User concern

The incremental rule from M6.2.11 could leave native controls scattered across Canvas Toolbar and Inspector code indefinitely. That creates a realistic risk that later feature work forgets the migration and continues accumulating one-off control geometry and CSS.

M6.2.12 therefore performs the broad migration now and adds a CI rule so future code cannot silently regress.

## Completion rule

Outside `src/ui`, business TSX must contain zero direct native interactive form/action controls:

```text
<button>      0
<select>      0
<input>       0
<textarea>    0
```

Structural button semantics such as Layer rows, Inspector collapsible headers and Property summary rows use the Base-UI-backed Studio `Pressable` primitive so their custom layout is preserved.

## New primitives in this slice

- `Pressable`
- `Input`
- `NumberInput`
- `Textarea`
- Studio-styled `ToolbarButton` on top of Base UI Toolbar

These extend the M6.2.11 set of Button / IconButton / SegmentedControl / Tabs / Select / Checkbox / Tooltip / Separator / Toolbar.

## Enforcement

Added `scripts/check-ui-primitives.mjs` and wired it into `npm run lint` after oxlint.

The script recursively scans `src/**/*.tsx`, excludes `src/ui`, and fails when business UI directly contains raw `<button>`, `<select>`, `<input>` or `<textarea>` tags.

This makes primitive-only business UI a repository invariant rather than a reminder for later work.
