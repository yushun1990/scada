# M6.3P1 managed SVG safe-passthrough authority amendment

Status: **dogfooding authority correction · 2026-09-05**

This document amends only the import/sanitization interpretation in `m6.3p1.0-svg-tag-authority.md`. It does not reopen M8, M9, the renderer boundary, or the managed SVG tag/rule identity model.

## Trigger

Real exported SVG files continued to fail after the first compatibility patch on declarations such as:

```text
style="enable-background:new 0 0 512 512"
```

`enable-background` is not script, an event handler, an external resource, or a second runtime authority. The failure exposed that the original freeze coupled two different boundaries:

1. whether static SVG content is safe to retain and render;
2. whether SCADA authoring/Visual Rules understand and may mutate that content.

Those boundaries must be separate.

## Corrected authority

`ManagedSvgDocument` remains the sole persisted SVG authority.

Managed SVG content is now classified as:

```text
unsafe / executable / externally dependent
    -> reject

safe static SVG semantics not owned by SCADA authoring
    -> preserve as sanitized passthrough inside ManagedSvgDocument

SCADA-controlled presentation fields
    -> normalize into first-class managed attributes
       and expose only through the existing authoring/rule surface
```

Therefore:

```text
importable != editable != Visual Rule targetable
```

This does not create a second renderer or a second SVG truth. Safe passthrough remains data inside the same managed document and is emitted by the same deterministic serializer into the same `assetRef` derivative.

## Controlled authoring surface remains unchanged

The M6.3P1 tag editor and tag Visual Rule targets remain limited to:

- `fill`
- `stroke`
- `stroke-width`
- `opacity`

Other retained attributes, elements, and residual static style declarations are not automatically editable or targetable merely because they are importable.

## Static style normalization

Controlled presentation declarations continue to normalize into managed attributes so later SCADA edits/rules have unambiguous precedence.

Safe declarations outside that controlled family may be retained as one sanitized, deterministic residual `style` attribute on the same managed element.

Example:

```xml
<svg style="enable-background:new 0 0 512 512;shape-rendering:geometricPrecision">
```

may remain importable without authorizing either declaration as a SCADA editable field.

Residual style must remain static and fail closed for:

- `javascript:` / legacy expression-like execution;
- external HTTP(S), file, or blob resources;
- non-internal `url(...)` references;
- `!important`, CSS custom-property authority, or declarations that cannot be deterministically split at import time.

`<style>` blocks remain a transient import concern. Supported static selector rules are expanded onto matching elements and the `<style>` element/class selector authority is removed before canonical persistence.

## Element and attribute safety model

The canonical managed parser no longer treats “not present in the SCADA editing whitelist” as equivalent to “unsafe.”

Static SVG namespace elements and non-event, non-namespaced attributes may be retained when they pass the common resource/script safety checks. This admits normal visual structures such as masks, patterns, markers, filters and filter primitives without making them authoring targets.

The following remain explicit hard rejects:

- `script` and executable handler constructs;
- `foreignObject`;
- SVG animation elements (`animate`, `animateMotion`, `animateTransform`, `set`, `discard`);
- `on*` event attributes;
- DTD/entity and processing-instruction execution surfaces;
- external HTTP(S), file, blob or host-relative dependencies;
- unsafe/non-static CSS;
- non-SVG namespace visible content not explicitly normalized away as editor metadata.

Internal `url(#...)` references are accepted only when the referenced source ID exists in the same managed document.

Self-contained raster `data:image` hrefs are allowed only on SVG image-bearing elements and do not authorize nested remote dependencies.

## Runtime boundary unchanged

The runtime chain remains exactly:

```text
ManagedSvgDocument
  -> Visual Rule resolution on controlled tag fields
  -> deterministic SVG serialization
  -> data:image/svg+xml
  -> existing CompositeComponentVisualRenderer
  -> browser Image / Konva.Image
```

There is no DOM SVG runtime, per-tag React renderer, second rule evaluator, selector service, or alternate standalone path.

## Governance consequence

This amendment supersedes the earlier sentence that every inline-style declaration must belong to the centrally allowlisted presentation subset.

The corrected rule is:

> every imported style declaration must be statically sanitizable; controlled declarations normalize into managed attributes, while safe non-controlled declarations may remain deterministic passthrough inside the same ManagedSvgDocument.

All other M6.3P1.0 authority decisions remain in force.
