# M9A1.3 — Scene v8 authored-state authority

Status: **accepted implementation slice pending PR merge**.

PR: #116

## Goal

Move Scene persistence from the historical mixed component `props` bag to explicit authored authority:

```text
Component scene node
├─ attributes          authored static configuration
└─ propertyFallbacks   authored/default Property-side fallback values
```

Effective runtime Property values are not Scene persistence authority.

## Accepted model

Scene v8 is the canonical in-memory and serialization model for component nodes:

```ts
{
  type,
  attributes,
  propertyFallbacks,
  bindings,
  behaviors,
  scadaSemantics,
}
```

`props` remains valid only as pre-v8 parser migration input. Group nodes retain their unrelated structural `props` (`designWidth` / `designHeight`).

## Migration authority

Scene v1–v7 component `props` are migrated through the current component definition:

```text
legacy props[field]
        ↓
current ComponentDefinition
        ├─ Attribute → attributes[field]
        └─ Property  → propertyFallbacks[field]
```

Missing authored values use the corresponding Attribute or Property definition default.

The migration does not copy the old mixed bag wholesale into `propertyFallbacks`. That would incorrectly reclassify authored presentation configuration as runtime-capable Property state.

Scene v7 persisted SCADA semantics remain readable and survive normalization to Scene v8.

## Fail-closed rules

- canonical Scene v8 component nodes require both `attributes` and `propertyFallbacks` records;
- a Scene v8 component node that also contains legacy `props` is rejected;
- undeclared v8 Attribute / Property fallback keys are rejected;
- Attribute and Property public names may not overlap in one `ComponentDefinition`, preserving one unique migration interpretation;
- runtime/effective Property state is never serialized into Scene authored state.

## Runtime/editor boundary

Runtime consumers now read `node.propertyFallbacks` as their authored Property base. Authored `node.attributes` remains outside `ComponentPropertyStore` and therefore outside runtime telemetry/derived propagation.

This slice deliberately does **not** complete the Renderer/Action runtime context split. That belongs to M9B1. It also does not implement the SCADA Inspector Attribute/Property UI separation; that belongs to M9A2.

## Compatibility evidence

Acceptance fixtures prove:

1. a raw Scene v7 node containing both `runningColor` and `state` in one legacy `props` object migrates to:
   - `attributes.runningColor`
   - `propertyFallbacks.state`
2. canonical Scene v8 serialization contains no component `props` authority;
3. a v8 component node that reintroduces `props` fails closed;
4. Scene v7 persisted SCADA semantics survive the v8 migration;
5. Work Package v1 remains independently versioned while nested Scene v6/v7 input normalizes to Scene v8;
6. Work Transfer remains compatible;
7. Standalone accepts retained Scene v7 and component-package v1 compatibility inputs, then runs only the canonical Scene v8 result;
8. Preview runtime propagation does not mutate authored Property fallbacks and authored Attributes never enter the Property store.
